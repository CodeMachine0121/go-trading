# Product Requirements Document — 重演只做現貨

**Status:** Draft
**Version:** v1.0
**Owner:** James Hsueh
**Stakeholders:** Engineering, QA

---

## 1. Background & Goal

### Problem Statement

重演現在認得四種交易模式，四種裡有三種借得到錢、有兩種做得了空。

那三種描述的其實是**合約帳戶**上的事：借錢、開空、撐不住就被強制平倉。
它們被寫進了重演**現貨行情**的那一套規則裡，於是有一個對不起來的東西：

> **一個借了二十倍、會被強制平倉的倉位，卻是拿現貨的高低價在判定它撐不撐得住。**

真實的合約不是這樣判的。合約有它自己的一個價格（市場用來判定一筆槓桿部位撐不撐得住的參考價），
而這個系統**才剛開始把那個價格抓回來**，抓回來之後還沒有任何人在用它。

所以現在這套槓桿與強制平倉是**拿現貨的行情假裝的合約**。
它跑得出數字，而那些數字看起來與真的一模一樣——**這是這裡最不該有的那種錯**。

**盤點現況更清楚**：使用者手上正在跑的每一份交易策略都是現貨，
每一台機器人的建議部位都是一倍槓桿。那三種模式**一個使用者都沒有**。

### Expected Outcome

- **重演只有一套規則：現貨。** 系統不再問「這一次要用哪一種規則重演」——只剩一種時那不是一個選擇。
- **借錢、開空、強制平倉整組不再存在**於重演裡。
- **現貨那套行為一個字都沒有改**——改的是它從四選一變成唯一的一種。
- **止損、止盈、交易成本、倉位大小模式完整保留**，現貨一樣用得到。
- **沒有人需要去修改自己存下的東西**：每一份交易策略、每一台機器人照舊讀得動、跑得動。
  系統自己會把「寫給哪一種帳戶」與「借幾倍」這兩欄清掉——它們記的全是預設值，
  而一個沒有人讀、卻還寫著「多空反手」的欄位，是一列在對後來的讀者說謊的資料。
- **送來一件系統已經不做的事，要說得出來**——不默默當作沒看見。
- 合約那條線（行情抓取、追蹤名單、背景同步、標的管理）**一行都不動**。

### Out of Scope

- **合約的重演**——它是另一件事，另外一刀做。它會有自己的行情、自己的價格基準、
  自己的借錢成本，不是把移走的這些原封搬回來。
- **合約行情的抓取、追蹤名單、背景同步、標的管理**——一行都不動。
- 止損與止盈（重演的與機器人的）。
- 交易成本。
- 倉位大小的模式與數值。
- 把已經存下的交易策略或機器人改掉。
- 策略腳本本身——腳本說出買入／賣出／持有，這件事與這一刀無關。

---

## 2. User Personas

- **Primary Role:** 交易策略的擁有者——本系統唯一的使用者，自己寫規則、自己養機器人、自己看成績單。
  他手上跑的全是現貨長抱；合約的部分他打算另外做。
- **Usage Context:** 坐下來調策略時在畫面上操作；也會請助手替他寫或改交易策略、跑重演；
  機器人在背景每隔一段時間送一則訊息到他手機上，他照著訊息自己下單。

## 3. User Stories & Acceptance Criteria

### US-01 — 重演照現貨的規則走倉位 [priority: P0]

**As a** 交易策略的擁有者，
**I want** 重演一律照現貨那一套規則模擬進出場，
**so that** 成績單講的是我真的做得到的那件事——拿現金換東西，賣掉就回到現金。

```gherkin
Scenario: 空手時聽到買入就開倉
  Given 帳上空手
  When 這一棒的信號是買入
  Then 開一個多倉

Scenario: 已經有倉位時再聽到買入不加碼
  Given 手上已經是多倉
  When 這一棒的信號是買入
  Then 倉位維持原樣，這一棒不記任何交易

Scenario: 有倉位時聽到賣出就平回現金
  Given 手上是多倉
  When 這一棒的信號是賣出
  Then 平倉，押下去的錢與這一筆賺賠回到可用資金
  And 之後帳上空手

Scenario: 空手時聽到賣出什麼都不發生
  Given 帳上空手
  When 這一棒的信號是賣出
  Then 什麼都不發生，這一棒不記任何交易
  And 帳上仍然空手,不會出現空倉

Scenario: 持平那一棒不動作
  Given 手上是多倉
  When 這一棒的信號是持平
  Then 倉位維持原樣，這一棒不記任何交易

Scenario: 整段重演的交易明細方向一致
  Given 一段行情從頭重演完，中間開過好幾次倉
  When 讀交易明細
  Then 每一筆的方向都是做多，一筆做空都沒有
```

### US-02 — 不必再挑「這一次要用哪一種規則」 [priority: P0]

**As a** 交易策略的擁有者，
**I want** 重演與交易策略都不再有交易模式這個選擇，
**so that** 我不必在一個只剩一種答案的問題上表態，也不會挑到一個這個系統其實模擬不準的選項。

```gherkin
Scenario: 什麼都不宣告就照現貨跑
  Given 一次重演，沒有宣告任何交易模式
  When 執行重演
  Then 照現貨的規則跑完，交出成績單

Scenario: 宣告現貨等於什麼都沒說
  Given 一次重演，宣告的交易模式是「現貨」
  When 執行重演
  Then 照現貨的規則跑完，結果與什麼都不宣告時逐格相同

Scenario: 宣告多空反手被整份拒絕
  Given 一次重演，宣告的交易模式是「多空反手」
  When 執行重演
  Then 整次重演被拒絕，說出這個系統的重演只做現貨
  And 不回傳任何部分結果

Scenario: 宣告槓桿做多被整份拒絕
  Given 一次重演，宣告的交易模式是「槓桿做多」
  When 執行重演
  Then 整次重演被拒絕，說出這個系統的重演只做現貨

Scenario: 宣告只做空被整份拒絕
  Given 一次重演，宣告的交易模式是「只做空」
  When 執行重演
  Then 整次重演被拒絕，說出這個系統的重演只做現貨

Scenario: 宣告一個認不得的詞同樣被整份拒絕
  Given 一次重演，宣告的交易模式是一個系統認不得的詞
  When 執行重演
  Then 整次重演被拒絕，說出這個系統的重演只做現貨

Scenario: 建立交易策略時沒有交易模式可填
  Given 一份新的交易策略，名稱、信號來源與兩個條件都齊備
  When 存這份交易策略
  Then 存得起來，它就是一份現貨的規則

Scenario: 建立交易策略時送來交易模式被整份拒絕
  Given 一份新的交易策略，其他欄位都齊備，而且宣告了交易模式
  When 存這份交易策略
  Then 整份被拒絕，說出這個系統的重演只做現貨
  And 這份交易策略沒有被存下來

Scenario: 這一刀之前存下的交易策略照舊跑得動
  Given 一份這一刀之前存下的交易策略，當初記著的是「現貨」
  When 拿它重演
  Then 照現貨的規則跑完，結果與這一刀之前逐格相同
```

### US-03 — 重演借不到錢，也不會被強制平倉 [priority: P0]

**As a** 交易策略的擁有者，
**I want** 重演不再模擬借錢與強制平倉，
**so that** 我不會拿到一張用現貨行情假裝出來的合約成績單。

```gherkin
Scenario: 不提槓桿的重演跑得完
  Given 一次重演，沒有提到槓桿
  When 執行重演
  Then 跑完並交出成績單
  And 成績單上沒有強平出場那一格

Scenario: 槓桿倍數填一等於沒有借錢
  Given 一次重演，槓桿倍數填一
  When 執行重演
  Then 跑完，結果與沒提槓桿時逐格相同

Scenario: 槓桿倍數填零等於沒有借錢
  Given 一次重演，槓桿倍數填零
  When 執行重演
  Then 跑完，結果與沒提槓桿時逐格相同

Scenario: 槓桿倍數大於一被整份拒絕
  Given 一次重演，槓桿倍數填二十
  When 執行重演
  Then 整次重演被拒絕，說出現貨是拿現金換東西、沒有人借錢給你
  And 不回傳任何部分結果

Scenario: 槓桿倍數小於一但不是零，同樣被整份拒絕
  Given 一次重演，槓桿倍數填零點五
  When 執行重演
  Then 整次重演被拒絕

Scenario: 一注承擔的就是押下去的錢
  Given 一次重演，某一注押下一百塊
  And 價格從進場價漲了一成之後平倉
  When 讀這一筆的賺賠
  Then 賺十塊

Scenario: 出場原因只剩三種
  Given 一段重演，開過好幾次倉也被止損掃出場過
  When 讀交易明細每一筆的出場原因
  Then 每一筆都是訊號出場、止損出場或止盈出場其中之一
  And 沒有任何一筆是強平出場

Scenario: 止損與止盈照舊生效
  Given 一次重演，給了止損距離與止盈距離
  When 執行重演
  Then 兩者照舊模擬，成績單上照舊有止損出場筆數與止盈出場筆數

Scenario: 交易成本照舊收
  Given 一次重演，給了進場成本率與出場成本率
  When 執行重演
  Then 照舊從可用資金扣，成績單上照舊有這次總共付了多少
```

### US-04 — 機器人只講得出現貨做得到的動作 [priority: P0]

**As a** 收機器人訊息的人，
**I want** 訊息的結論只寫我做得到的動作、建議部位不再提槓桿，
**so that** 我照著訊息下單時，不會被一個我其實開不了的倉位說法帶著走。

```gherkin
Scenario: 買入那一側寫買入
  Given 這一輪的結論是買入
  When 送出這一輪的訊息
  Then 結論那一句寫「買入」
  And 訊息裡沒有講交易模式的那一行

Scenario: 賣出那一側寫出場
  Given 這一輪的結論是賣出
  When 送出這一輪的訊息
  Then 結論那一句寫「出場」
  And 訊息裡沒有講交易模式的那一行

Scenario: 各來源怎麼說照舊抄信號的字
  Given 這一輪有兩個信號來源，一個說買入、一個說持有
  When 送出這一輪的訊息
  Then 「各來源怎麼說」那幾行照舊寫買入與持有
  And 只有結論那一句講動作

Scenario: 建議部位不再印槓桿與名目
  Given 一台機器人的建議部位，部位資金一萬、全押
  When 這一輪建議開倉
  Then 訊息印出開倉金額一萬
  And 訊息裡沒有槓桿那一行，也沒有名目那一行

Scenario: 建議部位的止損在參考價下方
  Given 一台機器人的建議部位帶了停損距離一成
  And 參考價是一百
  When 這一輪建議開倉
  Then 止損價是九十，並且在訊息上寫成往下

Scenario: 建立機器人時送來大於一的槓桿被整台拒絕
  Given 一台新的機器人，建議部位裡填槓桿二十倍
  When 存這台機器人
  Then 整台被拒絕，說出現貨是拿現金換東西、沒有人借錢給你
  And 這台機器人沒有被存下來

Scenario: 建立機器人時槓桿填一等於沒填
  Given 一台新的機器人，建議部位裡填槓桿一倍
  When 存這台機器人
  Then 存得起來，行為與沒填槓桿時逐字相同

Scenario: 這一刀之前建立的機器人照舊跑
  Given 一台這一刀之前建立的機器人，當初記著槓桿一倍
  When 它跑一輪並送出訊息
  Then 它照舊跑完並送出訊息，建議的金額與兩個出場價與這一刀之前逐格相同
  And 訊息上那一行改稱開倉金額，因為押下去的就是那筆錢本身，不再是押金
```

### US-05 — 助手不再替我挑一個不存在的選項 [priority: P1]

**As a** 請助手寫規則、跑重演的人，
**I want** 助手手上沒有交易模式與槓桿這兩個欄位可以填，
**so that** 它不會替我挑一個系統其實會拒絕、或模擬不準的設定。

```gherkin
Scenario: 助手建立交易策略時說不出交易模式
  Given 我請助手替我建立一份交易策略
  When 助手把這份交易策略交出去
  Then 這份交易策略存得起來
  And 助手沒有交易模式這個欄位可以填

Scenario: 助手跑重演時說不出槓桿
  Given 我請助手替我重演一份交易策略
  When 助手發動這次重演
  Then 重演照現貨的規則跑完
  And 助手沒有槓桿倍數這個欄位可以填
```

### US-06 — 合約那條線一行都不動 [priority: P0]

**As a** 正在把系統往合約推的擁有者，
**I want** 這一刀完全不碰合約的行情抓取與標的管理，
**so that** 合約重演將來要站的地基仍然在那裡，而且一直有資料進來。

```gherkin
Scenario: 合約追蹤名單原封不動
  Given 合約的追蹤名單上有幾個標的
  When 這一刀做完之後查這份名單
  Then 名單與這一刀之前逐項相同

Scenario: 合約行情一根都沒少
  Given 系統已經抓回一批合約 K 線
  When 這一刀做完之後查這些合約 K 線
  Then 一根都沒少，內容與這一刀之前逐格相同

Scenario: 合約的背景抓取照舊
  Given 合約的背景抓取每分鐘跑一輪
  When 這一刀做完之後
  Then 它照舊每分鐘跑一輪，抓回來的東西與這一刀之前性質相同
```

## 4. Business Flow & Logic

### Core Business Rules

**R1 — 重演唯一的一套規則（現貨）**

| 這一棒的信號 | 手上空手 | 手上有多倉 |
| :--- | :--- | :--- |
| 買入 | 開一個多倉 | 當作沒聽到 |
| 賣出 | **什麼都不發生** | 平倉，錢回到可用資金，之後空手 |
| 持平 | 不動作 | 不動作 |

- **同一棒不會既平又開。**
- **永遠不會出現空倉**；交易明細每一筆的方向都是做多。
- **借不到錢**：押下去多少就承擔多少，沒有債主，也就沒有人會來平你的倉。

**R2 — 送來一件系統已經不做的事**

判準只有一條：**它會不會改變答案。**

| 送來的東西 | 怎麼辦 | 為什麼 |
| :--- | :--- | :--- |
| 沒有宣告交易模式 | **接受** | 本來就沒說 |
| 宣告「現貨」 | **接受** | 它就是現在唯一的那一種 |
| 宣告另外三種的任何一種 | **整份拒絕** | 他要的是另一件事，而系統會給他一張不是那件事的成績單 |
| 宣告一個認不得的詞 | **整份拒絕** | 同上，而且更沒把握他要什麼 |
| 槓桿倍數留白、零或一 | **接受** | 三者本來就都是「沒有借錢」 |
| 槓桿倍數大於一 | **整份拒絕** | 他要借錢，而這裡沒有人借錢給他 |
| 槓桿倍數小於一且非零 | **整份拒絕** | 既有規則，一字不改 |

**拒絕一律是整份拒絕**，不回傳任何部分結果——半張成績單比沒有成績單更容易被當真。

**R3 — 出場原因從四種變三種**

訊號出場、止損出場、止盈出場。**強平出場不再存在**。

**R4 — 一注承擔的金額**

＝ **押下去的金額**。賺賠、進場成本、出場成本都照它算。
（在這一刀之前它是押注金額乘上槓桿倍數；沒開槓桿時兩者本來就相等，所以既有的每一個數字都沒變。）

**R5 — 機器人訊息**

- 結論那一句：買入那一側寫 `買入`，賣出那一側寫 `出場`。
- **不多一行講交易模式。**
- 「各來源怎麼說」那幾行照舊寫買入／賣出／持有。
- 建議部位：印開倉金額、止損價、止盈價、會虧多少、會賺多少；**不印槓桿，也不印名目**。
- 止損永遠在參考價下方、止盈永遠在上方。

### Edge Cases

- **已經存下的交易策略記著「現貨」**：讀得動、跑得動，結果逐格相同。
- **已經存下的機器人記著槓桿一倍**：跑得動，建議的每一個數字逐格相同；
  訊息上唯一改的是「保證金」改稱「開倉金額」。
- **這一刀之前「什麼都不宣告」的重演**：以前意思是多空反手，現在意思是現貨。
  同一支腳本同一段行情**跑出來的數字會不一樣**。這是這一刀唯一會安靜改變的既有行為，
  而它之所以可以安靜，是因為那種呼叫從來沒有明白表示過它要的是多空反手；
  明白表示過的（宣告了模式的）一律被拒絕，不會安靜地變。
- **重演一段完全沒有觸發任何交易的行情**：不是錯誤，照舊交出成績單。
