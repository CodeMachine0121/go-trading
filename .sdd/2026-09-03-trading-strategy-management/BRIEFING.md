# 交易策略管理 — Briefing（討論摘要）

> 這份是與 James 討論後的原始共識摘要，作為 `/clarify` 的輸入。
> 正式的需求共識文件是同資料夾的 `BRIEF.md`。

## 起心動念

目前有一支 `POST /indicator-calculations`：呼叫端把一段自己寫的程式碼（**策略腳本**）連同
交易標的、計算根數、指標值種類一起送進來，系統當場執行、回傳算出來的值，**算完就丟**。

James 想把每一支策略腳本**留下來**——寫過的策略要能被記住、被叫回來、被改、被刪，
而不是每次都要重新貼一次程式碼。

## 這個切片要做什麼

替「策略」建立一份可長期保存的清單，並提供完整的建立／讀取／修改／刪除。

### 一支策略要記住哪些事

| 要記的東西 | 說明 |
| :--- | :--- |
| 識別碼 | 系統給的流水號，用來指名這一支策略 |
| 策略名稱 | 人看的名字，**不得重複** |
| 策略腳本 | 策略本體，那一段程式碼 |
| 指標值種類 | 這支策略算出來的值長什麼樣：一個數字／一串數字／一個是非／一串是非 |
| 彙總刻度 | 這支策略要吃多粗的 K 線：五分鐘／十五分鐘／一小時／四小時／一天 |
| 計算根數 | 這支策略要吃幾根 K 線 |
| 建立時間、最後修改時間 | 系統自動記 |

### 為什麼「多久一根」與「幾根」要分成兩個欄位

一支策略需要多少資料，是「一根多久」乘上「要幾根」。
兩者拆開，同一段回看長度可以有不同的粗細——
「一小時 × 24 根」與「五分鐘 × 288 根」都是回看一天，但看到的東西完全不同。

### 「多久一根」為什麼只有那五種

已經確認過背景抓取的行為：系統每五分鐘去行情來源抓一次，**只抓五分鐘 K 線**，
一根一根存進資料庫。五分鐘是規則不是參數。

因此任何更長的刻度都只能由五分鐘 K 線併出來，
而五種刻度剛好都是五分鐘的整數倍（1、3、12、48、288 根），全部組得出來。
系統既有的彙總機制（`GET /k-candles/series` 用的那一套）也已經支援這五種。

所以策略的彙總刻度**沿用系統既有的那五種**，不另立第二套詞彙、不接受任意分鐘數。

## 明確的取捨與界線

- **「輸出值」指的是輸出的型別，不是上次算出來的數字。**
  策略是食譜，存食譜就好；值每次跑每次算，不存在策略身上。
- **這個切片不碰指標計算。**
  指標計算目前是直接讀原始五分鐘 K 線、沒有彙總，
  而且「排除最新一根」這條規則在較長的刻度下會不夠（最新那個刻度區間可能只裝了一半）。
  這兩件事都是真的要處理，但**留到下一個切片**，本切片只把策略本身建起來。
- **交易標的不存在策略身上。** 一支策略應該能套用在不同市場上。
- **不做刪除的軟刪除、不做版本歷史、不做誰擁有哪支策略。** 個人專案，單一使用者。

## 讀取要提供哪兩種

1. 以識別碼指名讀一支
2. 讀全部

## 驗證要求

- 策略名稱不得重複。
- 彙總刻度只能是那五種，其餘一律拒絕——建立與修改**都要**驗。
  在程式碼裡用列舉型別限制住，不要讓非法值有機會存進資料庫。

## 開發約定

- 每個段落與整合各自 commit 一次。
- Commit message 用英文並遵循 Conventional Commits。
- Commit message 不得出現任何 SDD 代號（測試案例編號、驗收條件編號、文件名稱）。
- 工作流程：`/clarify` → `/prd` → `/architecture` → `/implement codefirst`
  → `/improve-codebase` → `/contract`。
