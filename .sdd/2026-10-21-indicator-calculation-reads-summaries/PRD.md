# Product Requirements Document (PRD) — 指標計算改取留存彙總

**Status:** Finalized
**Version:** v1.0
**Owner:** James Hsueh
**Stakeholders:** 交易服務後端

---

## 1. Background & Goal (Why & Goal)

- **Problem Statement:** 看盤的人在合約圖上以一天為刻度、畫面約三個月時，每算一次指標最多要等約兩秒；現貨同樣慢，只是輕一些。
  指標計算至今仍把要看的那一段**每一分鐘**的 K 線全部翻出來重新合併（一天刻度約九十五格＝十三萬多根一分鐘 K 線），
  但看圖本身早已改取**留存彙總**；合約另外把那一段**每五分鐘一筆**的持倉統計全部翻出來（約兩萬七千筆），
  其實每一格只用得到收盤前最近且夠新的那一筆；資金費率結算與持倉統計也是一個等完才拿下一個。
- **Expected Outcome:**
  - 指標計算以一小時、四小時、一天為刻度時取**留存彙總**，翻的一分鐘 K 線從「整段」降為「最多今天這一天」。
  - 合約指標的持倉統計每一格只取一筆完整資料。
  - 以比特幣合約、一天刻度、約九十五格量測：翻出的資料筆數與耗時都要記錄改前改後，**耗時至少降到改前的五分之一**。
  - **算出來的每一個值、每一個時間、計算根數、實際採用根數、每一種拒絕都與現在完全相同。**
- **Out of Scope:**
  - 回測（逐根重演）的讀取：它還需要一分鐘 K 線本身，且跨刻度規則不同，延後。
  - 任何對外請求與回應格式、拒絕訊息文字。
  - 留存彙總本身的合併、作廢、背景補齊輪。
  - 一分鐘、五分鐘、十五分鐘刻度（沒有留存彙總，維持現行做法）。

## 2. User Personas

- **Primary Role(s):** 看盤的人（網頁看盤工作區上的指標）、策略機器人與外掛工具（呼叫指標計算）。
- **Usage Context:** 拖動或切換圖表時反覆要求指標計算；機器人每一輪也會算。

## 3. User Stories & Acceptance Criteria

### US-01 — 粗刻度指標計算取留存彙總 [priority: P0]
**As a** 看盤的人, **I want** 粗刻度的指標很快算出來, **so that** 拖圖、切刻度不必等。

```gherkin
Scenario: 走完的日子取留存彙總，算出的值與逐分鐘合併相同
  Given 比特幣合約過去一百天每天都有行情且都已彙總好
  When 以一天為刻度、看最近三個月算指標
  Then 九十五個指標值、每一格的起始時間、計算根數與實際採用根數，與逐分鐘合併算出的完全相同
  And 翻出的一分鐘 K 線不超過今天這一天份

Scenario: 還沒彙總好的日子一天一天補好後照用
  Given 要看的那一段有三天還沒彙總好
  When 以一天為刻度算指標
  Then 那三天被補成留存彙總
  And 算出的指標值與逐分鐘合併相同

Scenario: 截止時間落在格子中間，那一格不用
  Given 計算截止時間是今天上午十點二十分
  When 以一小時為刻度算指標
  Then 最後一格是今天九點那一格，十點那一格不採用

Scenario: 截止時間剛好落在格子邊界，邊界之前那一格採用
  Given 計算截止時間剛好是今天零點
  When 以一天為刻度算指標
  Then 最後一格是昨天那一格

Scenario: 細刻度維持逐分鐘合併
  When 以十五分鐘為刻度算指標
  Then 指標值與現在相同，且不取留存彙總
```

### US-02 — 往前找到湊滿計算根數為止 [priority: P0]
**As a** 看盤的人, **I want** 停牌、休市的空檔不影響要看幾格, **so that** 改快之後結果完全不變。

```gherkin
Scenario: 中間停牌十天，跳過空檔繼續往前湊滿
  Given 某合約中間有十天沒有任何行情
  When 以一天為刻度要三十格
  Then 採用最近三十個有行情的日子，與逐分鐘合併相同

Scenario: 台股只算有行情的交易日
  Given 台股週末與夜間沒有行情
  When 以一天為刻度要六十格
  Then 採用最近六十個有行情的交易日，與逐分鐘合併相同

Scenario: 行情歷史不夠時以可用根數計算
  Given 行情歷史只有二十天，最大回看根數為五
  When 以一天為刻度要三十格
  Then 計算根數回報三十、實際採用根數回報二十

Scenario: 可用根數低於最少可算根數照舊拒絕
  Given 行情歷史只有三天，最大回看根數為五
  When 以一天為刻度算指標
  Then 計算被拒絕，說出可用三根、至少要五根

Scenario: 行情歷史最早那一天不完整照舊採用
  Given 行情歷史從某天下午才開始，且不夠湊滿
  When 以一天為刻度算指標
  Then 最早那一格只含那天下午的行情，照舊採用
```

### US-03 — 持倉統計每一格只取用得到的那一筆 [priority: P0]
**As a** 看盤的人, **I want** 合約指標不必搬整段每五分鐘的持倉統計, **so that** 合約指標也一樣快。

```gherkin
Scenario: 每五分鐘都有統計，每一格只取收盤前最後一筆
  Given 某天每五分鐘都有持倉統計
  When 以一天為刻度算合約指標
  Then 那一格採用二十三點五十五分那一筆
  And 那一天只取這一筆完整的持倉統計

Scenario: 統計中途斷了，採用格子內最後一筆
  Given 某天的持倉統計只到中午十二點
  When 以一天為刻度算合約指標
  Then 那一格採用十二點前最後那一筆

Scenario: 整格沒有統計，持倉數字是零
  Given 某天一筆持倉統計都沒有
  When 以一天為刻度算合約指標
  Then 那一格的持倉數字全部是零

Scenario: 一分鐘刻度可採用前四分鐘內的那一筆
  Given 某一分鐘內沒有持倉統計，但它收盤前五分鐘內有一筆
  When 以一分鐘為刻度算合約指標
  Then 那一格採用那一筆

Scenario: 剛好落在收盤那一刻的統計屬於下一格
  Given 一筆持倉統計剛好落在某一格的收盤時刻
  When 算合約指標
  Then 那一格不採用它，下一格才可能採用
```

### US-04 — 互不相干的資料同時去拿 [priority: P1]
**As a** 看盤的人, **I want** 資金費率結算與持倉統計同時取得, **so that** 等待時間不是相加。

```gherkin
Scenario: 同時取得，結果與依序取得相同
  Given 資金費率結算與持倉統計都正常
  When 算合約指標
  Then 每一格的資金費率、是否在格內結算、持倉數字與依序取得時相同

Scenario: 任何一種取不到，整次計算失敗
  Given 持倉統計那一邊出錯
  When 算合約指標
  Then 整次計算失敗，不回傳任何指標值
```

## 4. Business Flow & Logic

- **核心規則（全部沿用，不新增）：**
  - 只採用走完的格子：計算截止時間所在那一格不用。
  - 計算根數＝要看幾格＋最大回看根數−1；往前找到湊滿為止，沒有行情的格子不算。
  - 湊不滿時以可用根數計算；低於最少可算根數即拒絕。
  - 行情歷史最早那一格可能不完整，照舊採用。
  - 合約每一格的資金費率取收盤前最近一次結算；持倉統計取收盤前最近一筆，且須在格子內或收盤前五分鐘內，否則為零。
- **新的取法：**
  - 粗刻度先取一段（估計夠湊滿的長度）；不夠時找出更早一筆行情所在的那一格，再往前取一段；直到湊滿或行情歷史到底。
  - 留存彙總的取法與看圖相同：走完的日子取留存彙總，今天與還沒走完的格子由一分鐘 K 線當場合併，缺的日子一天一天補。
- **Edge Cases:**
  - 取資料任何一步出錯：整次計算失敗，與現在相同。
  - 行情歷史完全沒有：照舊回報可用零根而拒絕。

## 6. Non-Functional Requirements

- **Performance:** 比特幣合約、一天刻度、約九十五格的一次指標計算，資料讀取耗時至少降到改前的五分之一；記錄改前改後的讀取筆數與耗時。
- **行為等價:** 以「同一份行情，新舊取法算出的指標輸入逐值相同」的檢驗保證不變，涵蓋全天候與台股、停牌空檔、歷史不足、截止時間在邊界與格中。
- **Security / Compatibility / Analytics:** N/A。

---

## 7. Dependencies & Risks

- **依賴:** 前一刀「粗刻度 K 線序列先彙總好再給」的留存彙總與作廢機制。
- **風險:** 留存彙總若與一分鐘 K 線不同步會讓指標值不同；由既有「一分鐘 K 線一變即作廢」保證。
- **副作用:** 指標計算會像看圖一樣替缺的日子補留存彙總（寫入），與看圖行為一致。
