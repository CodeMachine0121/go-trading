# Product Requirements Document (PRD)

**Status:** Draft · **Version:** v1.0 · **Owner:** James Hsueh

---

## 1. Background & Goal

- **Problem Statement:** 使用者要拿 AI 研發短線策略，但重演有四個地方讓短線的成績單不可信：
  重演得不夠長（與單次查詢共用上限、跑太久時沒有任何一處說太久了）、成交得太漂亮（一律收盤成交）、
  成績單說不出短線要看的事、沒有樣本外。
- **Expected Outcome:**
  - 重演有自己的格數上限（預設五萬）與整次允許時間（預設九十秒），超過就清楚地拒絕或中止。
  - 重演可以選**下一格開盤成交**。
  - 成績單多五格：獲利因子、每筆期望值、平均持倉時間、最大連續虧損筆數、成本佔毛利。
  - 重演可以給**驗證起點**，多交出調參段與驗證段兩張各自從空手開始的成績單。
  - 以上現貨與合約兩種重演、策略腳本與交易策略兩種對象一律適用；什麼都沒說時**每一個既有的數字**與今天一字不差
    （成績單只多出五格新指標與成交時點、驗證起點兩項說明）。
- **Out of Scope:** 參數掃描、多段滾動驗證、顯著性檢定；限價掛單、掛單吃單分別、每筆最低手續費；
  不同刻度混用、四棵條件樹、合約機器人；讓算式只看得到宣告的回看格數。

---

## 2. User Personas

- **Primary Role:** 系統的使用者（策略腳本與交易策略擁有者），通常透過外部 AI 助理反覆發動重演。
- **Usage Context:** 在一段期間上調參數，再拿後面一段沒看過的期間驗證；比較不同成交時點與成本下的成績單。

---

## 3. User Stories & Acceptance Criteria

以下若無特別說明：初始資金 10,000、全押、無成本、無滑點、止損止盈不設、成交時點為收盤成交。
「重演」泛指現貨與合約兩種重演、策略腳本與交易策略兩種對象。

### US-01 — 重演有自己的格數上限與允許時間 [P0]

**As a** 使用者, **I want** 重演走得夠長、而且太久時系統自己說清楚,
**so that** 我拿得到足以判斷短線策略的成績單，也不會對著一個沒有回應的請求乾等。

```gherkin
Scenario: 在重演上限之內
  Given 重演格數上限五萬格
  And 這次重演要用四萬格
  When 重演
  Then 照常交出成績單

Scenario: 超過重演上限
  Given 重演格數上限五萬格
  And 這次重演要用六萬格
  When 重演
  Then 整次拒絕，並說出這一段要用六萬格、最多五萬格

Scenario: 重演不再受單次查詢上限限制
  Given 單次查詢上限一千、重演格數上限五萬
  And 這次重演要用兩千格
  When 重演
  Then 照常交出成績單

Scenario: 超過整次允許時間
  Given 整次重演允許時間九十秒
  And 這次重演到九十秒還沒跑完
  When 重演
  Then 整次中止，並說出重演在九十秒內沒跑完
  And 不交出任何成績單
```

### US-02 — 可以選下一格開盤成交 [P0]

**As a** 使用者, **I want** 讓信號在下一格開盤才成交,
**so that** 短線策略不會賺到收盤那一刻其實已經過去的價格。

```gherkin
Scenario: 收盤成交與今天相同
  Given 第一格收盤 100 說買入、第二格開盤 101
  When 以收盤成交重演
  Then 以 100 開倉

Scenario: 下一格開盤成交
  Given 第一格收盤 100 說買入、第二格開盤 101
  When 以下一格開盤成交重演
  Then 以 101 開倉，進場時間是第二格

Scenario: 最後一格的信號不成交
  Given 最後一格說買入
  When 以下一格開盤成交重演
  Then 沒有開倉

Scenario: 開盤進場的那一格就判出場價位
  Given 第一格說買入、第二格開盤 100、最低 97、止損 2%
  When 以下一格開盤成交重演
  Then 第二格開盤進場，同一格以 98 止損出場

Scenario: 下一格開盤平倉
  Given 持有多倉，第三格說賣出、第四格開盤 105
  When 以下一格開盤成交重演
  Then 以 105 平倉

Scenario: 開盤那一刻的資金費率結算不收付
  Given 合約、一小時刻度，第一格說買入，第二格 01:00 開盤成交
  And 01:00 有一次資金費率結算
  When 以下一格開盤成交重演
  Then 那一次結算不收付，累計資金費用為 0

Scenario: 合約的滑點照舊套在開盤成交價上
  Given 合約、滑點 0.1%，第一格說買入、第二格開盤 100
  When 以下一格開盤成交重演
  Then 成交於 100.1

Scenario: 認不得的成交時點
  Given 成交時點填「盤中」
  When 重演
  Then 整次拒絕，並說出只有收盤成交與下一格開盤成交兩種
```

### US-03 — 成績單多五格 [P0]

**As a** 使用者, **I want** 成績單說得出每筆平均賺多少、賺的夠不夠付成本、最多連虧幾次,
**so that** 我分得出一支短線策略是真的有優勢，還是只是交易次數多。

```gherkin
Scenario: 一般情形
  Given 已平倉交易淨損益 +300、−100、+200、−100
  When 看成績單
  Then 獲利因子 2.5、每筆期望值 75、最大連續虧損 1 筆

Scenario: 一筆都沒虧
  Given 已平倉交易淨損益 +100、+50
  When 看成績單
  Then 獲利因子不適用、每筆期望值 75

Scenario: 一筆都沒平倉
  Given 沒有任何已平倉交易
  When 看成績單
  Then 獲利因子、每筆期望值、平均持倉時間、成本佔毛利都不適用
  And 最大連續虧損 0 筆

Scenario: 打平打斷連續虧損
  Given 已平倉交易淨損益 −10、−20、0、−5
  When 看成績單
  Then 最大連續虧損 2 筆

Scenario: 成本佔毛利
  Given 兩筆已平倉交易扣成本前各賺 100、交易成本合計 50
  When 看成績單
  Then 成本佔毛利 25%

Scenario: 價差本身沒賺時成本佔毛利不適用
  Given 已平倉交易扣成本前合計 −40、交易成本合計 10
  When 看成績單
  Then 成本佔毛利不適用

Scenario: 平均持倉時間
  Given 兩筆已平倉交易分別持有 1 小時與 3 小時
  When 看成績單
  Then 平均持倉時間 2 小時

Scenario: 還開著的那一注不算進五格
  Given 結束時還開著一注，另有一筆已平倉交易淨賺 100
  When 看成績單
  Then 每筆期望值 100、最大連續虧損 0 筆
```

### US-04 — 樣本外驗證 [P0]

**As a** 使用者, **I want** 在一段期間上調參數、另一段沒看過的期間上驗證,
**so that** 我分得出一支策略是真的有效，還是只是背熟了那段行情。

```gherkin
Scenario: 切出調參段與驗證段
  Given 期間 1/1 到 1/31，驗證起點 1/21
  When 重演
  Then 交出整段、調參段（1/1 到 1/20）、驗證段（1/21 到 1/31）三張成績單

Scenario: 驗證段從空手開始
  Given 同上，調參段在 1/20 收盤時抱著一注多倉
  When 重演
  Then 驗證段的成績單從初始資金、空手開始
  And 那一注不出現在驗證段的交易明細裡

Scenario: 驗證段的算式看得到驗證起點以前的歷史
  Given 算式要看前 20 格才說得出信號
  When 重演，走到驗證段的第一格
  Then 算式看得到驗證起點以前的 20 格，說得出信號

Scenario: 驗證起點等於期間起點
  Given 驗證起點等於期間起點
  When 重演
  Then 整次拒絕，並說出驗證起點必須落在期間之內

Scenario: 驗證起點晚於期間終點
  Given 驗證起點晚於期間終點
  When 重演
  Then 整次拒絕，並說出驗證起點必須落在期間之內

Scenario: 驗證段湊不出任何一格
  Given 驗證起點之後一格走完的刻度區間都沒有
  When 重演
  Then 整次拒絕，並說出驗證段湊不出任何一格

Scenario: 沒給驗證起點
  Given 沒給驗證起點
  When 重演
  Then 只交出整段一張成績單，與今天一字不差
```

## 4. Business Flow & Logic

- **格數上限與允許時間：** 重演格數上限與整次允許時間是系統設定（預設五萬格、九十秒）；單次查詢上限不再限制重演。
  允許時間從開始跑算式起算，涵蓋所有信號來源；超過即整次中止。每一格算式各自的允許時間照舊。
- **下一格開盤成交：**
  - 第 N 格的信號（或交易策略在第 N 格的結論）在第 N+1 格開盤成交；每一格依序：
    ①（合約）收付**正好在這一格開盤那一刻**的資金費率結算（只有帶著倉位進入這一格的那一注要付）→
    ② 以開盤價執行上一格留下的信號 → ③（合約）收付這一格**開盤之後**的其餘結算 →
    ④ 判出場價位（含剛在這一格開盤開的倉）→ ⑤ 以收盤價記資金曲線。
  - 所以剛在這一格開盤才開的倉，不收付開盤那一刻的結算，但照常收付同一格稍晚的結算（例如一天刻度裡的 08:00、16:00）。
  - 最後一格的信號不成交。
  - 收盤成交時順序與今天相同。
- **五格指標（只看已平倉交易）：**
  - 獲利因子 ＝ 淨損益大於零的合計 ÷ |淨損益小於零的合計|；沒有虧損或沒有交易 → 不適用。
  - 每筆期望值 ＝ 淨損益合計 ÷ 筆數；平均持倉時間 ＝ 出場時間減進場時間的平均；沒有交易 → 不適用。
  - 最大連續虧損筆數 ＝ 淨損益小於零連續最多幾筆；打平與賺錢打斷；沒有交易 → 0。
  - 成本佔毛利 ＝ 交易成本合計 ÷ 扣成本前損益合計（扣成本前 ＝ 淨損益 ＋ 兩端成本；合約另加回資金費用，資金費用不算成本）；
    扣成本前合計不大於零 → 不適用。
- **其他說明：** 成交時點的拼法不分大小寫、前後空白不算；成本佔毛利以比例呈現（25% 即 0.25）；
  允許時間以秒說出；系統內建助手的重演也受同一個格數上限與允許時間約束。
- **樣本外驗證：**
  - 一格歸哪一段看它**從什麼時候開始**：開始時間早於驗證起點的歸調參段，等於或晚於的歸驗證段
    （驗證起點落在一格中間時，那一格歸調參段——它開始的那一刻還沒有到驗證起點）。
  - **調參段或驗證段任一段湊不出一格**即整次拒絕，說出是哪一段湊不出；驗證起點等於期間終點也以「必須落在期間之內」拒絕。
  - 兩段**各自**從初始資金、空手重演；信號由同一次逐格執行得到（算式在驗證段看得到之前的全部歷史）。
  - 整段成績單照舊從頭走到尾。
  - 分段成績單與整段同一種形狀（現貨對現貨、合約對合約），各有自己的資金曲線、交易明細與打架格數。

## 6. Non-Functional Requirements

- **Performance:** 整次允許時間預設九十秒，低於常見反向代理的一百秒切斷，讓系統自己先說清楚。
- **Security:** 沿用既有登入與歸屬規則。
- **Analytics / Tracking:** N/A。

---

## 7. Dependencies & Risks

- **Dependencies:** 部署設定需寫入重演格數上限（正式環境目前單次查詢上限已是十萬，重演上限應至少維持這個能力）。
- **Risks:** 長重演的回應很大（資金曲線每格一點）；由呼叫的那一端（外部助理、畫面）自己取樣呈現。
