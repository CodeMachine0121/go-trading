# 幣安自動下單設定 — Requirements Brief

## Goal

策略機器人到今天為止**只說話、不下單**：每一輪判出信號，只在信號變了的時候送到擁有者的 Telegram。
使用者最終想要的是讓機器人**用他自己的幣安帳戶替他下單**。

這個切片只做「下單之前要準備好的兩件事」，**不下任何一張單**：

1. 一位使用者留下自己的一組**幣安交易金鑰**（幣安發給他的 API Key 與 Secret Key 兩串），
   系統在存下之前先問幣安這組金鑰能不能用、能交易哪幾種市場。
2. 每一台策略機器人多一個**自動下單**開關，表達「這台機器人是否允許用那組金鑰替我下單」。

開關打開之後真的去下單，是下一個切片的事。這個切片結束時，**機器人仍然只說話**——
開關打開與否，每一輪的行為一模一樣。

**幣安交易金鑰是一把可以動用他真錢的鑰匙。** 所以它比 Telegram 的機器人金鑰更不能被讀走：
Secret Key 設定進去之後再也拿不回來、連結尾都不給看，在留存處也不裸著躺著。

## Requirements

### 一、幣安交易金鑰記著什麼

- **API Key**——幣安發給這組金鑰的公開識別串。**不得為空白**；前後空白不予保留。
- **Secret Key**——幣安發給這組金鑰、用來證明「這筆指令真的是他下的」的那一串。**不得為空白**；前後空白不予保留。
  兩串缺一不可：只有 API Key，下一個切片什麼單都下不了。
- **可交易市場**——存下當時，幣安說這組金鑰開了哪幾種交易權限：**現貨**、**合約**，或兩者都有。
- **設定時刻**——這組金鑰是何時留下的。一律以世界標準時間表示與儲存。
- **每一位使用者最多只有一組。** 再存一次是**覆蓋**，不是多留一組。
- **一位使用者只讀得到、也只改得動自己的那一組。** 別人有沒有設定、設了什麼，他一概看不到。
- 只有**目前登入者**做得了以上任何一件事；認不出人來一律拒絕並要求先登入。

### 二、金鑰不以原樣示人

- 讀回時，**API Key 只顯示最後 4 個字**，前面一律遮掉——足以認出「是不是同一組」。
- **Secret Key 一個字都不顯示**，連結尾也不給。它沒有「認出是哪一組」的用途，API Key 的結尾已經做到了。
- **完整的兩串設定之後就再也拿不回來。** 要換，就兩串重新填一次。
- 讀回時一併顯示**可交易市場**與**設定時刻**。

### 三、金鑰不裸著留存

- 兩串在留存處都是**被鎖起來的**，規矩與 Telegram 的機器人金鑰相同：
  必須讀得回來才用得了，所以只能上鎖、不能算成算不回去的東西；**開這道鎖的東西不放在留存處旁邊**。
- **系統沒有拿到開鎖的東西時，一律拒絕留存**，並說明是系統目前存不了，不是使用者填錯了什麼；
  **不會退而求其次改用不上鎖的方式存**。

### 四、存下之前先問幣安

- 每一次存入，系統先拿這兩串去問幣安：**這組金鑰被不被接受、開了哪幾種交易權限**。
- **至少要開了現貨或合約其中一種交易權限才收**；兩種都沒開（例如只能讀）即拒絕，並說出這組金鑰沒有任何交易權限。
- **不檢查「不能有什麼權限」**——例如開了提現權限，這個切片不擋。
- **幣安那一側的拒絕要分得出是哪一種**，至少分出：**金鑰不被接受**、**連不上幣安**、**等太久**、**沒有任何交易權限**。
  四種要做的事不同（重填金鑰／稍後再試／稍後再試／去幣安開權限），合成同一句話就沒有人知道該怎麼辦。
- 詢問**有等待上限**。等太久就當作沒存成，並說明是等太久。
- **任何一種存不成，原本存著的那一組（以及所有機器人的自動下單開關）原封不動。**
- **可交易市場只在存入當下記一次。** 之後使用者在幣安那邊改了權限，系統不會自己發現；要重存一次才會更新。

### 五、移除金鑰

- 一位使用者可以把自己的那一組**整組移除**。
- **沒有設定的人要求移除，也回報「現在沒有設定」，不算失敗。**
- 移除時，**他每一台開著自動下單的機器人一律改成關閉**（見第七節）。

### 六、自動下單開關

- **掛在策略機器人上**，現貨機器人與合約機器人都有；每一台各自決定。
  不掛在交易策略上：交易策略是一套規則，會被回測、被市集複製、被好幾台機器人同時引用；
  「要不要用真錢」是跑在某個標的上的那一台機器人的決定。
- **新建的機器人預設關閉；既有的每一台機器人也都是關閉。**
- **隨時改得動**——執行中或已停止都可以開、可以關。
- **打開時有兩道關卡**：
  - 這位使用者**必須已經存了一組幣安交易金鑰**，否則拒絕並說要先完成幣安交易金鑰設定；
  - 那組金鑰的**可交易市場必須涵蓋這台機器人的種類**：現貨機器人要有現貨、合約機器人要有合約，
    否則拒絕並說出這組金鑰沒有哪一種交易權限。
- **關掉永遠可以**，不需要任何前提——包括沒有金鑰的時候。關掉是緊急煞車，不能有任何理由擋住它。
- 只有**機器人擁有者**改得動；別人的機器人一律回答找不到。
- **這個切片裡，開關不改變機器人的任何行為**：每一輪照樣判信號、照樣只送 Telegram，不下任何單。

### 七、金鑰變了，對不上的開關自動關掉

- **系統裡不允許存在「開著自動下單、卻沒有能用的金鑰」的機器人。**
- 金鑰**被移除**時：這位使用者每一台開著自動下單的機器人都改成關閉。
- 金鑰**被換成另一組**時：新那一組的可交易市場**不涵蓋**的那一種機器人，自動下單改成關閉；涵蓋的維持原狀。
- 換存**失敗**時，什麼都不變（見第四節）。

### 八、外掛（替使用者代操的 AI 助理）只能讀

- 外掛**讀得到**：一台機器人的自動下單是開是關、這位使用者**有沒有**設定幣安交易金鑰（與可交易市場）。
- 外掛**讀不到**任何一段金鑰內容，連 API Key 的結尾也不給。
- 外掛**沒有**存入金鑰、移除金鑰、打開或關掉自動下單這幾件事可以做——不是擋下來，是沒有這件事。
  理由：金鑰不該經過一段 AI 對話；「讓機器人拿真錢下單」必須由人親手按。

## Out of Scope

- 開關打開後真的下單、平倉、設止損止盈——留給下一個切片。
- 檢查「不能有什麼權限」（例如拒收開了提現權限的金鑰）。
- 定期重新向幣安確認權限、偵測使用者在幣安那邊改了權限或刪了金鑰。
- 幣安以外的交易所；幣安的測試環境。
- 一位使用者存多組金鑰、或不同機器人用不同的金鑰。
- 自動下單開著時的任何額外通知。

## Open Decisions

Items the PRD author should resolve:

- 幣安詢問的等待上限是幾秒。
- 「可交易市場」裡的合約，指的是哪一種合約帳戶（以 USDT 計價的永續合約為主）。
- UL-MAP 對**策略機器人**的定義「不下單、不代操——它只說話」要怎麼改寫：
  這個切片結束時這句話仍然成立，但要補上「多一個自動下單開關，目前不生效」。
- **幣安交易金鑰**、**自動下單**、**可交易市場**加入 UL-MAP；
  **不得與既有的「機器人金鑰」（Telegram）混用同一個詞**。
- 自動因金鑰變動而被關掉的那幾台機器人，是否要在機器人上留下「為什麼被關掉」的記號。

## Context / Background

- 規矩大量沿用 `2026-09-10-telegram-delivery`：每人一份、覆蓋、只有本人、上鎖留存、缺開鎖的東西即拒絕、
  移除不存在的設定不算失敗、外部那一側的失敗要分得出種類、有等待上限、失敗不動已存設定。
- 與 Telegram 不同之處：**Secret Key 連結尾都不顯示**；存入**前**就先問外部（Telegram 是另外送測試訊息）。
- 開關放機器人而非交易策略，是因為交易策略會被市集複製、被多台機器人引用，也會被回測使用。
- 外掛只能讀，是延續「交易服務內建的行情對話助手刻意不開放給外掛」的同一個理由：
  某些決定不該由 AI 代為做出。
- 本切片同時在前端（`go-trading-frontend`）與外掛（`go-trading-mcp`）各有一份對應的 brief，業務規則以本份為準。
