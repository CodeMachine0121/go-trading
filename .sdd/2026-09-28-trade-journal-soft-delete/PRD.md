# Product Requirements Document (PRD) — 交易日誌軟刪除

**Status:** Finalized
**Version:** v1.0
**Owner:** James Hsueh
**Stakeholders:** Engineering

---

## 1. Background & Goal (Why & Goal)

- **Problem Statement:** 使用者發現一筆尚未平倉的合約交易「不見了」，追查後才知道是透過正常的刪除操作移除的。目前刪除一筆交易會連同開倉平倉紀錄、附註、檢討一起永久抹除，事後既無法確認被刪的是什麼，也無法救回。
- **Expected Outcome:**
  - 刪除一筆合約或現貨交易後，它對擁有者的呈現與今天完全相同（看不到、改不了），但交易的完整內容與刪除時間**仍保存在系統中**。
  - 營運方事後能確認「某筆交易是在什麼時候被刪除的」。
  - 刪除一筆持倉中／持有中的交易後，使用者仍能立刻為同一標的（合約另加同一方向）重新記一筆。
- **Out of Scope:**
  - 還原（取消刪除）已刪除交易。
  - 讓使用者或管理者瀏覽已刪除交易。
  - 已刪除交易的定期永久清除。
  - 刪除單一筆開倉/平倉紀錄或買進/賣出（持倉中的修正用）——仍是當場移除。
  - 使用者帳號被移除時連帶移除其交易的行為。
  - 記錄「是誰、從哪裡刪除」的稽核資訊，以及限制只有網頁上的本人才能刪除。

---

## 2. User Personas

- **Primary Role(s):**
  - **交易者**：記錄自己手動交易的使用者，從網頁或授權的外掛操作自己的合約／現貨交易日誌。
  - **營運方**：系統維運者，在使用者回報交易不見時，需要能確認發生了什麼。
- **Usage Context:** 交易者在任何時候刪除一筆記錯或不要的交易；營運方在事後調查時查看系統保存的資料。

---

## 3. User Stories & Acceptance Criteria

### US-01 — 刪除後交易仍保存，但對擁有者消失 [priority: P0]
**As a** 交易者, **I want** 刪除的交易從我的日誌裡消失, **so that** 我的日誌只呈現我要的交易；**同時** 營運方仍保有它的內容以便事後追查。

```gherkin
Scenario: 刪除自己的交易後它仍保存並記下刪除時間
  Given 我有一筆未刪除的合約交易 #12
  When 我刪除 #12
  Then 刪除成功
  And #12 連同它的開倉平倉紀錄與附註仍保存在系統中
  And #12 被標為已刪除交易，並記下刪除的時間

Scenario: 刪除自己的現貨交易同樣只是標為已刪除
  Given 我有一筆未刪除的現貨交易 #20
  When 我刪除 #20
  Then 刪除成功
  And #20 連同它的買進賣出紀錄仍保存在系統中，並被標為已刪除交易

Scenario: 列表不列出已刪除交易，總筆數也不計入
  Given 我的合約交易 #12 已刪除
  And 我另有一筆未刪除的合約交易 #13
  When 我列出我的合約交易
  Then 只列出 #13
  And 總筆數為 1

Scenario: 只剩已刪除交易時列表是空的
  Given 我唯一的一筆合約交易 #12 已刪除
  When 我列出我的合約交易
  Then 列表是空的
  And 總筆數為 0

Scenario: 依狀態篩選時也不列出已刪除交易
  Given 我持倉中的合約交易 #12 已刪除
  When 我只列出持倉中的合約交易
  Then 列表不含 #12

Scenario: 查看已刪除交易回覆找不到
  Given 我的合約交易 #12 已刪除
  When 我查看 #12
  Then 回覆「找不到」這筆交易

Scenario: 再刪一次已刪除交易回覆找不到
  Given 我的合約交易 #12 已刪除
  When 我再刪除 #12 一次
  Then 回覆「找不到」這筆交易

Scenario: 刪除別人的交易回覆找不到且不影響它
  Given 另一位使用者有一筆未刪除的合約交易 #27
  When 我刪除 #27
  Then 回覆「找不到」這筆交易
  And #27 仍是未刪除，對它的擁有者照常可見

Scenario: 改動上線前記下的交易照常出現
  Given 我在這次改動上線前記下的合約交易 #5
  When 我列出我的合約交易
  Then #5 照常出現在列表中
```

### US-02 — 已刪除交易不能再修改 [priority: P0]
**As a** 交易者, **I want** 已刪除的交易無法再被修改, **so that** 已刪除的內容維持刪除當下的樣子，不會被誤改。

```gherkin
Scenario: 為已刪除的持倉中交易加平倉紀錄回覆找不到
  Given 我持倉中的合約交易 #12 已刪除
  When 我為 #12 加一筆平倉紀錄
  Then 回覆「找不到」這筆交易
  And #12 的開倉平倉紀錄不變

Scenario: 修正或刪除已刪除交易的一筆開倉紀錄回覆找不到
  Given 我持倉中的合約交易 #12 已刪除
  When 我修正或刪除 #12 的一筆開倉紀錄
  Then 回覆「找不到」這筆交易

Scenario: 為已刪除的已平倉交易寫檢討回覆找不到
  Given 我已平倉的合約交易 #12 已刪除
  When 我為 #12 寫檢討
  Then 回覆「找不到」這筆交易

Scenario: 為已刪除交易加附註、改計畫或改型態標籤回覆找不到
  Given 我的合約交易 #12 已刪除
  When 我為 #12 加附註、改進場計畫或改型態標籤
  Then 回覆「找不到」這筆交易

Scenario: 為已刪除的現貨交易加一筆賣出回覆找不到
  Given 我持有中的現貨交易 #20 已刪除
  When 我為 #20 加一筆賣出
  Then 回覆「找不到」這筆交易

Scenario: 未刪除的交易照舊可以修改
  Given 我持倉中的合約交易 #13 未刪除
  When 我為 #13 加一筆平倉紀錄
  Then 照舊記下這筆平倉紀錄
```

### US-03 — 已刪除交易不計入統計與實盤 vs 回測 [priority: P0]
**As a** 交易者, **I want** 統計與實盤 vs 回測只反映我保留的交易, **so that** 我刪掉的記錯的交易不會污染我的成績。

```gherkin
Scenario: 績效統計不計入已刪除交易
  Given 我已平倉的合約交易 #12 賺 100 且已刪除
  And 我已平倉的合約交易 #13 虧 50 且未刪除
  When 我看績效統計
  Then 只計入 #13：1 筆已平倉交易、淨損益 -50

Scenario: 現貨統計不計入已刪除交易
  Given 我已平倉的現貨交易 #20 已刪除
  And 我已平倉的現貨交易 #21 未刪除
  When 我看現貨統計
  Then 只計入 #21

Scenario: 實盤 vs 回測不拿已刪除交易對照
  Given 依交易策略 A 的已平倉交易 #12 已刪除、#13 未刪除
  When 我看交易策略 A 的實盤 vs 回測
  Then 只拿 #13 對照

Scenario: 策略的已平倉交易全被刪除時等同沒有實單
  Given 依交易策略 A 的已平倉交易只有 #12，且已刪除
  When 我看交易策略 A 的實盤 vs 回測
  Then 呈現為沒有任何已平倉實單，不重演
```

### US-04 — 刪除持倉中交易會釋出持倉名額 [priority: P0]
**As a** 交易者, **I want** 刪掉一筆記錯的持倉中交易後能立刻重記, **so that** 刪除不會把我卡住。

```gherkin
Scenario: 刪除持倉中的合約交易後可以重記同標的同方向
  Given 我 BTCUSDT 做多持倉中的交易 #12 已刪除
  When 我新記一筆 BTCUSDT 做多
  Then 記下成功，成為新的持倉中交易

Scenario: 未刪除的持倉中交易照舊擋下同標的同方向
  Given 我有一筆未刪除的 BTCUSDT 做多持倉中交易 #13
  When 我新記一筆 BTCUSDT 做多
  Then 拒絕，並說已有持倉中的交易 #13

Scenario: 刪除持有中的現貨交易後可以重記同標的
  Given 我 2330 持有中的現貨交易 #20 已刪除
  When 我新記一筆 2330 買進
  Then 記下成功，成為新的持有中交易

Scenario: 記到交易日誌連結不把已刪除交易當成已有持倉中
  Given 我 BTCUSDT 做多持倉中的交易 #12 已刪除
  When 我打開一則 BTCUSDT 做多的記到交易日誌連結
  Then 預填的是新增一筆交易，而不是對 #12 加開倉紀錄
```

### US-05 — 刪除標籤時只算未刪除的交易 [priority: P1]
**As a** 交易者, **I want** 只貼在已刪除交易上的標籤可以刪掉, **so that** 我不會因為看不到的交易而刪不掉標籤。

```gherkin
Scenario: 只貼在已刪除交易上的標籤可以刪除
  Given 標籤「追價進場」只貼在合約交易 #12 上，且 #12 已刪除
  When 我刪除標籤「追價進場」
  Then 刪除成功

Scenario: 仍貼在未刪除交易上的標籤照舊刪不掉，且只算未刪除的筆數
  Given 標籤「追價進場」貼在合約交易 #12（已刪除）與現貨交易 #21（未刪除）上
  When 我刪除標籤「追價進場」
  Then 拒絕，並說還有 1 筆交易貼著它
```

## 4. Business Flow & Logic

- **Flow:** 擁有者刪除 → 確認是自己的且未刪除（否則「找不到」）→ 標為已刪除交易並記下刪除時間 → 之後所有讀取與修改都把它當作不存在。
- **Core Business Rules:**
  - **已刪除等同不存在（對擁有者）**：列表與總筆數、查看、績效統計／現貨統計、實盤 vs 回測、記到交易日誌連結的「已有持倉中」判斷、標籤「還貼著幾筆」一律排除已刪除交易。
  - **「找不到」一致**：已刪除交易與別人的交易對任何操作一律回同一句「找不到」，不透露差異。
  - **持倉名額**：「同一位使用者、同一合約標的、同一方向最多一筆持倉中」與「同一標的最多一筆持有中」只算未刪除的交易。
  - **內容凍結**：已刪除交易的內容維持刪除當下的樣子。
  - **既有資料**：改動上線前的所有交易視為未刪除。
  - 合約與現貨兩本日誌規則相同。
- **Edge Cases:**
  - 同時對同一筆交易發出兩次刪除：只會有一次成功，另一次回「找不到」或同樣成功皆可，但交易只會被標記一次、刪除時間不被覆寫成更晚的時間。
  - 刪除當下儲存失敗：刪除不成立，交易維持未刪除，回覆暫時失敗。

## 6. Non-Functional Requirements

- **Performance:** 列表、統計、實盤 vs 回測的回應時間不因保留已刪除交易而明顯變慢。
- **Security:** 歸屬規則不變——只有擁有者能刪除自己的交易；已刪除與否不對他人透露任何差異。
- **Compatibility:** 對外回覆的形狀不變；既有的網頁前端與外掛不需修改即可運作。
- **Analytics / Tracking:** N/A。

---

## 7. Dependencies & Risks

- **External Dependencies:** 無。
- **Known Risks:**
  - 任何一條讀取路徑漏掉排除已刪除交易，都會讓已刪除交易「復活」在列表或統計裡——需逐一涵蓋所有讀取路徑。
  - 「同標的最多一筆持倉中」的保證若沒有同步只算未刪除交易，刪除持倉中交易後會無法重記。
