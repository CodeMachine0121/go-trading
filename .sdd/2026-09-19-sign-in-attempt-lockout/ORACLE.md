# Oracle — 登入失敗鎖定

每一列的「預期」**只從 PRD 推導**，在任何實作存在之前寫下。
寫測試時斷言的期望值一律抄這裡，**不准從跑出來的結果回填**。

政策：門檻 3 次、鎖定期長 7 天。`T` = 這次登入發生的時刻。

---

## A · `SignInLockoutDomain`（業務規則的所在地）

| # | Given（這位使用者留存的狀態） | When | Then（預期） | 出處 |
| :-- | :--- | :--- | :--- | :--- |
| A1 | 次數 0、解除時刻 nil | `Refusal()` | `nil` | 沒被鎖住的帳號照常登入 |
| A2 | 次數 0、解除時刻 nil | `AfterFailure()` | `{1, nil}` | 第一次猜錯只是記一筆 |
| A3 | 次數 1、解除時刻 nil | `AfterFailure()` | `{2, nil}` | 還沒到門檻 |
| A4 | 次數 2、解除時刻 nil | `AfterFailure()` | `{3, T+7d}` | 第三次當場鎖住 |
| A5 | 次數 2、解除時刻 nil | `AfterSuccess()` | `{0, nil}` | 第三次猜對了就不鎖 |
| A6 | 次數 3、解除時刻 `T+3d` | `Refusal()` | `SignInLockedError{T+3d}` | 鎖住期間一律拒絕 |
| A7 | 次數 3、解除時刻**正好** `T` | `Refusal()` | `nil` | 到了那一刻就算解開 |
| A8 | 次數 3、解除時刻 `T+1s` | `Refusal()` | `SignInLockedError{T+1s}` | 差一秒不算解開 |
| A9 | 次數 3、解除時刻 `T-1s`（已過期） | `AfterFailure()` | `{1, nil}` | **期滿後從 1 重新數起，不是 4** |
| A10 | 次數 3、解除時刻 `T-1s`（已過期） | `AfterSuccess()` | `{0, nil}` | 成功一律歸零 |
| A11 | 次數 3、解除時刻 `T-1s`（已過期） | `Refusal()` | `nil` | 過期即視為沒被鎖住 |
| A12 | 零值使用者（次數 0、解除時刻 nil） | `Refusal()` | `nil` | 查無此人時流程要照舊往下走 |
| A13 | 次數 5（超過門檻）、解除時刻 nil | `AfterFailure()` | `{6, T+7d}` | 到達**或超過**門檻都鎖 |

> A13 不在 PRD 的情境裡，是防禦性的一列：門檻若被調小，既有的列會一夕超過它。
> 「等於才鎖」會讓那些列永遠鎖不起來。

## B · `UserService.SignIn`（把規則接上登入流程）

| # | Given | When | Then（預期） | 出處 |
| :-- | :--- | :--- | :--- | :--- |
| B1 | 使用者存在、沒被鎖住 | 正確密碼 | 成功發出憑證；**寫入 `{0, nil}`** | 照常登入 |
| B2 | 使用者存在、次數 0、沒被鎖住 | 錯誤密碼 | `ErrCredentialsRejected`；**寫入 `{1, nil}`** | 第一次猜錯 |
| B3 | 使用者存在、次數 2、沒被鎖住 | 錯誤密碼 | `ErrCredentialsRejected`；**寫入 `{3, T+7d}`** | 第三次當場鎖住 |
| B4 | 使用者存在、次數 2、沒被鎖住 | 正確密碼 | 成功；**寫入 `{0, nil}`** | 第三次猜對就不鎖 |
| B5 | 使用者被鎖住到 `T+3d` | 錯誤密碼 | `SignInLockedError{T+3d}`；**比對密碼不被呼叫**；**不寫入任何狀態** | 鎖住期間拒絕、不累加、不延後 |
| B6 | 使用者被鎖住到 `T+3d` | **正確**密碼 | `SignInLockedError{T+3d}`；**比對密碼不被呼叫** | 正確密碼也進不來 |
| B7 | 解除時刻正好是 `T` | 正確密碼 | **成功**；寫入 `{0, nil}` | 到了就算解開 |
| B8 | 解除時刻 `T-1s`、次數 3 | 錯誤密碼 | `ErrCredentialsRejected`；寫入 `{1, nil}` | 期滿後從 1 數起 |
| B9 | **查無此電子郵件** | 任意密碼 | `ErrCredentialsRejected`；**比對密碼仍然被呼叫**（掩護用）；**不寫入任何狀態** | 不存在的帳號問不出東西 |
| B10 | 查無此電子郵件 | 連續 5 次 | 每次都 `ErrCredentialsRejected`，**永遠不是** `SignInLockedError`；一次都沒寫入 | 同上 |
| B11 | 使用者存在、次數 2 | 錯誤密碼，但**寫入失敗** | 回傳**寫入的那個錯誤**，不是 `ErrCredentialsRejected` | 記不下來就是整次失敗 |
| B12 | 使用者**待開通**、次數 2 | 錯誤密碼 | `ErrCredentialsRejected`；寫入 `{3, T+7d}` | 開通狀態與鎖定互不相干 |
| B13 | 使用者存在、沒被鎖住 | 正確密碼，但**寫入失敗** | 回傳寫入的那個錯誤；**不發出憑證** | 同 B11 |

> **B5 / B6 的「比對密碼不被呼叫」是這一組最重要的一條。** 它同時驗到兩件事：
> 鎖定檢查在比對之前（效能要求），以及鎖住期間走不到累加那條路（所以「不延長」不是靠自律）。

## C · `UserRepository`（狀態真的寫得進去）

| # | Given | When | Then（預期） |
| :-- | :--- | :--- | :--- |
| C1 | 一位已存在的使用者 | `SaveSignInLockoutState(id, {3, T+7d})` | 那一列的次數是 3、解除時刻是 `T+7d` |
| C2 | 一位被鎖住的使用者 | `SaveSignInLockoutState(id, {0, nil})` | 那一列的次數是 0、解除時刻是**空的** |
| C3 | 不存在的識別碼 | `SaveSignInLockoutState(...)` | `ErrUserNotFound` |
| C4 | 一位被鎖住、次數 3 的使用者 | `ChangePasswordProof(id, 新證明)` | 密碼證明換了、**次數歸零、解除時刻清空**、每一段登入階段作廢 |
| C5 | 新建立的使用者 | 讀回來 | 次數是 0、解除時刻是空的 |
| C6 | 一位已存在的使用者，但儲存當下答不出來 | `SaveSignInLockoutState(...)` | 回傳**儲存的那個錯誤**，而**不是** `ErrUserNotFound`——寫不進去與查無此人是兩件事，上游對它們的反應不同 |

> C6 是覆蓋率關卡逼出來的一列：原本的五列跑不到「儲存答不出來」那條路。
> 補測試而不是刪程式碼，因為那條路真的會走到——上游正是靠它分辨「這次登入失敗」與「這個位址沒人用」。

## 刻意不寫測試的

- **續用與登出不讀鎖定狀態。** ARCH 說「不是讀了之後放行，是根本不讀」——
  沒有程式碼可以測。要防的是下一個人加進去，而那件事靠 ARCH 的說明擋，不靠測試。
- **讀後寫的競態。** 已知且接受（ARCH §7），寫一個測試也只會把接受的行為釘死成規格。
