# Oracle — 算式隔間同時上限

每一列的「預期」**只從 PRD 推導**，在任何實作存在之前寫下。斷言的期望值一律抄這裡。

名額相關的列透過公開 proxy 驗證（名額池是 proxy 的內部細節，只在 isolation 上共用一份）；
「佔住名額」一律用一支無窮迴圈算式、以可取消的 context 控制它何時結束。

---

## A · 名額內照常運作（US-01）

| # | Given | When | Then（預期） |
| :-- | :--- | :--- | :--- |
| A1 | 上限 2；沒有其他計算；收盤 100、110、120 | Execute | `close = 120` |
| A2 | 上限 2；1 個被佔住 | Execute，發動者只等 5 秒 | 在 5 秒內得到 `close = 120`（沒有排隊等那個被佔住的） |

## B · 排隊與忙碌（US-02）

| # | Given | When | Then（預期） |
| :-- | :--- | :--- | :--- |
| B1 | 上限 1；佔住者 0.3 秒後結束 | Execute，發動者不設時限 | 得到 `close = 120` |
| B2 | 上限 1；一直被佔住 | Execute，發動者只等 0.2 秒 | 錯誤是 `ErrIndicatorScriptCompartmentsBusy`、**不是** `ErrIndicatorScriptFailed`；說法含「忙碌中」 |
| B3 | 重演允許時間已用完、proxy 回報忙碌 | RunBacktest / 合約 RunContractBacktest | 錯誤是 `ErrIndicatorScriptCompartmentsBusy`、**不是** `ErrBacktestTimeAllowanceSpent` |
| B4 | 應用層回傳忙碌錯誤 | 指標計算 / 重演 / 交易策略重演端點 | `503`，body 含 `compartmentsBusy: true` |

## C · 名額一定歸還（US-03）

上限 1；前一個計算以下列方式結束後，立刻 Execute（發動者只等 5 秒）→ 得到 `close = 120`。

| # | 前一個計算如何結束 |
| :-- | :--- |
| C1 | 算式刻意 panic →「算式執行失敗」 |
| C2 | 允許時間 0.3 秒的無窮迴圈 →「未能算完」 |
| C3 | 發動者中途離開 →「發動它的請求已經結束」 |
| C4 | 排隊中發動者離開（佔住者之後才放手） |

## D · 機器人優先（US-04）

| # | Given | When | Then（預期） |
| :-- | :--- | :--- | :--- |
| D1 | 上限 1；被佔住；先排隨選、再排機器人 | 佔住者放手 | 機器人那一次先完成，隨選其後 |
| D2 | 上限 1；被佔住；兩個隨選先後排 | 佔住者放手 | 先排的先完成 |
| D3 | 機器人一輪錯誤是忙碌 | 判斷這一輪 | 跳過（不停機器人），`HaltsTheBot() == false` |

## E · 處理器時間上限（US-05）

| # | Given | When | Then（預期） |
| :-- | :--- | :--- | :--- |
| E1 | 隔間收到的處理器時間上限 1 秒、允許時間 1 小時；無窮迴圈 | 直接交給隔間 | 隔間在 30 秒內結束、沒有回答、非正常結束，已用處理器時間 ≥ 約 1 秒 |
| E2 | 允許時間 2 秒；一千根快算完的重演 | ExecuteForEachCandle | 一千個結果（既有測試已涵蓋） |
