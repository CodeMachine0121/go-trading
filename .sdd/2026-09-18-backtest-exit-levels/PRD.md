## 1. Background & Goal (Why & Goal)

### Problem Statement

上一刀讓機器人的訊息建議「押多少、止損放哪、止盈放哪」。
那一刀交付時，訊息底下不得不印一行話：

> ⚠️ 回測沒有把止損止盈算進去

那一行是誠實的，但它指出的是**這個系統目前最大的一個落差**：

- 訊息叫使用者去掛一個停損。
- 而他決定要不要信這台機器人的依據——那張回測成績單——
  是在**完全沒有停損**的前提下算出來的。

兩者不是「有一點誤差」。同一段歷史、同一支腳本：

| | 第一棒 | 第二棒 | 第三棒 | 結果 |
|---|---|---|---|---|
| 行情 | 收 100（說買入） | 高 103、低 **97** | 收 **110** | — |
| **沒有停損** | 全押一萬 | 抱著 | 抱著 | **11000（+10%）** |
| **停損 2%（98）** | 全押一萬 | **被掃出場** | 空手 | **9800（−2%）** |

**一個 +10%，一個 −2%，差 12 個百分點。** 而成績單只說得出前者。

使用者拿著一張「+10%」的成績單，去掛一個會讓它變成「−2%」的停損。
他不是被誤導了一點，他是在看一個**不存在的策略**的成績。

### Expected Outcome

發動回測時可以多說兩件事：**止損距離**與**止盈距離**（各自選填的百分點）。
填了，重演就**真的把它們算進去**——被掃出場就是被掃出場，
最終權益、總報酬率、勝率、最大回落、交易明細**全部反映那些出場**。

不填，就**一個數字都不變**。

於是使用者第一次能回答那個他一直該問的問題：
**「我打算掛的那個停損，在過去這一年會讓這支腳本賺還是賠？」**

### Out of Scope

| 不做 | 為什麼 |
|:---|:---|
| 移動停損（trailing stop） | 止損價進場算好就不動。要它跟著走得先決定「跟著什麼走」，那是一整個設計 |
| 手續費與滑點 | 仍然一概不計。成交在止損價本身。這一刀只加停損，不順手改別的假設 |
| 用更細的 K 線還原盤中順序 | 它會讓「同一棒兩個都碰到」有真正的答案，但要每一棒再撈一層細 K 線——另一次取數 |
| 把兩個距離存回策略腳本或交易策略 | 它們跟「這段時間、這些參數值」同一類：**跟著這一次走** |
| 與機器人身上那組距離共用 | 同名不同事。機器人的是「每一輪要建議什麼」，這裡的是「這一次重演怎麼模擬」 |
| 同一次回測比較「有停損 / 沒停損」 | 一次一種，要對照就跑兩次——與交易模式一字不差的理由 |
| 依止損距離反算部位大小（風險百分比法） | 押多少仍然是既有那三種 |

## 2. User Personas

| Persona | 描述 | 他在這一刀裡要什麼 |
|:---|:---|:---|
| **策略調校者（James 本人）** | 唯一使用者。寫腳本、跑回測、讀成績單、調整，一圈一圈來 | 他正打算給機器人配一個停損。他要知道那個停損在過去會讓他賺還是賠——**在掛上去之前** |
| **AI 助手（透過 MCP）** | 代替他跑那一整圈 | 「建規則 → 回測 → 讀成績單 → 調整」。調整裡最自然的一項就是換一組停損，所以它必須說得出那兩個數字 |

## 3. User Stories & Acceptance Criteria

### US-01 — 發動回測時說得出兩個出場距離 [priority: P0]

> **作為** 策略調校者
> **我想要** 在發動回測時填上止損距離與止盈距離
> **以便** 讓成績單算的是我真正打算跑的那個策略，不是一個沒有停損的幻想版本

**Acceptance Criteria**

- **AC-01.1** 兩個欄位皆為**選填的百分點**。
- **AC-01.2** 兩個都留白 → **一概不計**：報告與這一刀之前**每一個數字逐字相同**。
- **AC-01.3** 只填止損 → 只算止損；止盈不存在（永遠不會因止盈出場）。
- **AC-01.4** 只填止盈 → 只算止盈。
- **AC-01.5** **兩種回測都要能說**：重演一支策略腳本、重演一份交易策略，行為一字不差。
- **AC-01.6** 任一距離**為負** → 整次拒絕，訊息說出是哪一個距離、以及「不得為負」。
- **AC-01.7** 任一距離**超過 100** → 整次拒絕，訊息說出「不得超過 100%——那會讓價格變成負數」。
- **AC-01.8** 距離正好 **100** → 送得出去。止損價正好是零，荒謬但算得出來，而
  「100% 是不是合法」這個問題在機器人那一側已經答過一次，兩邊必須答同一句話。
- **AC-01.9** 拒絕時**指向的是「出場距離」這一組**（一個欄位名），
  由訊息本身說出是止損還是止盈那一格。

> **為什麼是一個欄位名而不是兩個**：這兩格在每一個提供它們的畫面上都是**併排填的一組**，
> 而拒絕的句子已經說出了是哪一個距離。多一個常數只是把句子裡已經有的那個詞再說一次。
> 這與既有的「時間範圍」是同一個判斷：它一個名字蓋住兩個時刻加一個刻度。

### US-02 — 被停損掃出場就是被掃出場 [priority: P0]

> **作為** 策略調校者
> **我想要** 重演在價格碰到我的止損價時真的把部位平掉
> **以便** 成績單上的那條權益曲線是我真的會經歷的那一條

**Acceptance Criteria**

以**第一棒收 100 說買入、全押一萬**（＝ 100 單位）為基準：

- **AC-02.1** 止損 2%（止損價 **98**）、第二棒**低 97** → **以 98 出場**，
  該筆虧 **200**，帳上 **9800**。
- **AC-02.2** 止損 2%、第二棒**低正好 98** → **出場**。碰到就是碰到。
- **AC-02.3** 止損 2%、第二棒**低 99** → **不出場**，部位繼續。
- **AC-02.4** 止盈 5%（止盈價 **105**）、第二棒**高 106** → **以 105 出場**，賺 **500**，帳上 **10500**。
- **AC-02.5** 用的是**那一棒的高低點**，不是收盤價。
  第二棒低 97 但收 101 照樣出場——停損是盤中被掃到的。
- **AC-02.6** **成交在止損價／止盈價本身**，不計滑點。
- **AC-02.7** 距離從**進場價**量起（不是從任何參考價）。
- **AC-02.8** 做多：止損在下、止盈在上。**做空：完全反過來**
  （止損 2% → 102，止盈 5% → 95）。
- **AC-02.9** **現貨模式照樣算**。現貨只做多，所以永遠只有「止損在下、止盈在上」那一種。

### US-03 — 那兩條時序規則不會偷走或多給任何一筆 [priority: P0]

> **作為** 策略調校者
> **我想要** 重演對「什麼時候開始檢查」與「同一棒碰到兩個」有一個說得清楚的答案
> **以便** 我不會拿到一張靠時序漏洞美化過的成績單

**Acceptance Criteria**

- **AC-03.1 進場那一棒不檢查。** 第一棒收 100 開多、止損 98，
  而**第一棒自己的低點是 96** → **不出場**。
  進場成交在收盤價，那一棒的低點在成交之前就已經發生過了。
- **AC-03.2 同一棒同時碰到止損與止盈 → 算止損。**
  止損 98、止盈 105、第二棒高 **106** 低 **97** → **以 98 出場，虧 200**。
- **AC-03.3** 被掃出場之後，**那一棒的信號照常判**：
  第二棒被止損掃出且第二棒信號是買入 → 先以 98 出場，**再以第二棒收盤價重新進場**。
  開倉次數 +1，交易明細多一筆。
- **AC-03.4** 被掃出場而那一棒信號是**持有** → 出場後空手，那一棒的權益曲線點是純現金。
- **AC-03.5** 重新進場後，止損價**從新的進場價重新量**。
  第三棒碰到新的止損價 → 再出場一次。
- **AC-03.6** 檢查順序在每一棒上固定是：**先看出場價位，再套用這一棒的信號**。

### US-04 — 成績單說得出出場是怎麼發生的 [priority: P0]

> **作為** 策略調校者
> **我想要** 知道有幾筆是被停損掃出去的
> **以便** 分辨「靠訊號賺到的 +8%」與「一路被停損削到只剩 +8%」

**Acceptance Criteria**

- **AC-04.1** 每一筆已平倉交易多帶一個**出場原因**：`signal` / `stopLoss` / `takeProfit`。
- **AC-04.2** 成績單多兩個數字：**止損出場筆數**、**止盈出場筆數**。
- **AC-04.3** 兩個距離都沒填 → 兩個數字都是 **0**，每一筆的原因都是 `signal`。
- **AC-04.4** 三筆交易（一筆訊號出場、兩筆被止損）→ 止損 **2**、止盈 **0**，
  三筆各自標出自己的原因。
- **AC-04.5** 結束時還開著的那一注**沒有出場原因**——它沒有出場。
  照舊不進交易明細，但照舊算進最終權益。
- **AC-04.6** 勝率、最大回落、總報酬率**全部**反映那些出場（它們讀的是同一段歷史）。

> **為什麼是兩個總數加逐筆原因，而不只是總數**：
> 總數答得出「有幾筆」，答不出「是哪幾筆」。而看交易明細的人問的正是後者——
> 那幾筆被掃掉的是不是都擠在同一段行情裡。

### US-05 — 助手也說得出那兩個距離 [priority: P0]

> **作為** AI 助手
> **我想要** 在發動重演時填上那兩個距離
> **以便** 我替使用者調停損時，說得出每一種停損的代價

**Acceptance Criteria**

- **AC-05.1** 兩個重演工具（腳本重演、交易策略重演）都多出這兩個**選填**參數。
- **AC-05.2** 說明要寫明：**留白就是不模擬出場**、距離是**從進場價**量的百分點、
  以及**同一棒兩個都碰到時算止損**。
- **AC-05.3** 助手不填 → 與這一刀之前一字不差。

---

### US-06 — 畫面上填得出那兩個距離、讀得出那兩個數字 [priority: P0]

> **作為** 策略調校者
> **我想要** 在回測表單上填那兩格、在成績單上看到出場筆數
> **以便** 不必為了試一個停損去開 MCP

**Acceptance Criteria**

- **AC-06.1** 回測條件區多一組「出場價位」欄位：止損距離、止盈距離，**皆選填**。
- **AC-06.2** 兩格留白 → 送出去的請求不帶這兩個值，成績單與之前一字不差。
- **AC-06.3** 距離不合法 → **當場不送出**，訊息標在這一組旁邊。
  句子與後端**逐字相同**（同一組規則不生第二套說法）。
- **AC-06.4** 成績單多顯示止損出場筆數與止盈出場筆數；
  **兩者皆為 0 且沒填距離時不顯示**（沒有模擬出場的那次，兩個零沒有任何資訊）。
- **AC-06.5** 交易明細每一列標出出場原因。
- **AC-06.6** 兩種回測畫面（腳本回測、交易策略回測）都有這一組。

---

### US-07 — 訊息裡那一行警告改寫，不是拿掉 [priority: P1]

> **作為** 訊息的讀者
> **我想要** 那一行說得出下一步
> **以便** 我知道要怎麼讓成績單算進這個停損

**Acceptance Criteria**

- **AC-07.1** 那一行**不刪掉**——不填距離的那次重演仍然不計，說它「已經算進去了」會是新的謊。
- **AC-07.2** 改成說得出下一步：**回測時把那兩個距離填上才會算進去**。
- **AC-07.3** MCP 建立機器人工具裡那句同義的警告同步改寫。
- **AC-07.4** 沒有部位規劃的機器人，訊息仍然**一個字都沒變**（它本來就沒有這一行）。

## 4. Business Flow & Logic

### 一棒怎麼走

```
對每一根 K 線（最舊到最新）：

  1. 先看出場價位              ← 這一刀新增
     有開著的部位嗎？
        沒有 → 跳過
        有   → 這一棒的高／低點碰到了止損價嗎？
                  碰到 → 以止損價平倉，原因＝止損，止損筆數 +1
                  沒碰到 → 碰到止盈價嗎？
                              碰到 → 以止盈價平倉，原因＝止盈，止盈筆數 +1
                              沒碰到 → 部位繼續

  2. 再套用這一棒的信號        ← 原本就有，一行都沒改
     （目標倉位、反手、平倉、開新倉、押多少、買不起就跳過）
     新開的部位在進場當下算好它自己的兩個出場價位

  3. 記一個權益曲線點（以這一棒收盤價計價）
```

**「先看價位，再套信號」這個順序本身就是「進場那一棒不檢查」那條規則。**
第 N 棒的部位是在第 N 棒的第 2 步開的，而第 1 步已經走過了——
所以它第一次被檢查是在第 N+1 棒。
不需要比對進場時間，不需要記「這是不是進場那一棒」。
**那條規則不是一個判斷，它是這個順序。**

### 一個部位的兩個出場價位

進場當下算一次就固定，與單位數同一個理由（每一棒重算會讓一個沒動的部位看起來在漂）：

| | 做多 | 做空 |
|:---|:---|:---|
| 止損價 | `進場價 × (1 − 止損距離%)` | `進場價 × (1 + 止損距離%)` |
| 止盈價 | `進場價 × (1 + 止盈距離%)` | `進場價 × (1 − 止盈距離%)` |
| 止損觸發 | `這一棒最低價 ≤ 止損價` | `這一棒最高價 ≥ 止損價` |
| 止盈觸發 | `這一棒最高價 ≥ 止盈價` | `這一棒最低價 ≤ 止盈價` |

距離為零 → 那個出場不存在（永遠不觸發）。

### Core Business Rules

| # | 規則 | 為什麼 |
|:--|:---|:---|
| BR-01 | 兩個距離**選填**，留白即不模擬 | 既有的每一次呼叫都沒有停損。替它們補一個預設值＝在沒人動手的情況下改掉他每一張成績單 |
| BR-02 | 距離為負、或超過 100 → **整次拒絕** | 負的會跑到價格的另一邊；超過 100 會讓價格變成負數。兩句話與機器人那一側**逐字相同** |
| BR-03 | 正好 100 送得出去 | 止損價是零，荒謬但算得出來。與機器人那一側同一個答案 |
| BR-04 | 距離從**進場價**量 | 重演裡沒有參考價，只有實際成交的那一筆 |
| BR-05 | 用**高低點**判，不用收盤價 | 停損是盤中被掃到的。用收盤價判等於假裝盤中沒發生過任何事 |
| BR-06 | **成交在那個價位本身** | 與「不計手續費、不計滑點」一致。這一刀不順手改別的假設 |
| BR-07 | **進場那一棒不檢查** | 成交在收盤價，那一棒的高低點在成交之前就發生過了 |
| BR-08 | 同一棒兩個都碰到 → **算止損** | K 線說不出順序。兩種讀法只有一種永遠不會讓成績單變好看 |
| BR-09 | 出場後**那一棒的信號照常判** | 止損在盤中、收盤在盤後，順序一致。吞掉那個信號＝讓一次停損順便吃掉一個無關的進場機會 |
| BR-10 | 重新進場 → 出場價位**從新進場價重算** | 它是新的一注。沿用舊價位等於把上一注的條件掛在這一注身上 |
| BR-11 | 每一筆帶**出場原因**；成績單帶**兩個出場筆數** | 同一個報酬率，兩個完全不同的故事 |
| BR-12 | 結束時還開著的那一注**沒有出場原因** | 它沒有出場。發明一個等於把一筆沒發生的交易寫進明細 |

### 沿用的既有規則（不生第二套說法）

| 沿用 | 從哪裡來 | 為什麼不重寫 |
|:---|:---|:---|
| 兩句距離拒絕的**措辭** | 機器人部位規劃的距離檢查 | 同一個 150 在兩張表單上必須得到同一句話 |
| 一個部位的方向、單位數、損益、平倉計價 | 既有的部位模型 | 停損出場與訊號出場的**平倉算法完全一樣**，只有價格與原因不同 |
| 押多少那三種 | 既有的部位大小模型 | 這一刀一個字都沒碰它 |
| 交易模式決定「賣出」是什麼意思 | 交易模式模型 | 出場價位只認方向，不認信號 |
| 拒絕帶欄位名的機制 | 既有的回測欄位錯誤 | 多一套等於前端要認兩種形狀 |

### Edge Cases

| 情境 | 行為 |
|:---|:---|
| 第一棒就開倉、第一棒低點已在止損價下 | **不出場**（BR-07） |
| 同一棒被止損掃出、信號又要求反手開空 | 先以止損價平多 → 再以收盤價開空。兩筆交易 |
| 止損掃出後帳上現金不足以開新倉 | 照既有規則**跳過開倉**，繼續空手。不是錯誤 |
| 止損距離 100%（止損價 0） | 價格不可能 ≤ 0（非正價格的部位開不起來），所以**永遠不觸發**。算得出來、也不騙人 |
| 止盈距離 100%（做空止盈價 0） | 同上，永遠不觸發 |
| 最後一棒才碰到止損價 | 照樣出場。那一棒的權益曲線點是純現金 |
| 部位開著、整段行情都沒碰到任何價位 | 與這一刀之前一字不差 |
| 兩個距離都填、但整段從沒觸發 | 成績單兩個筆數都是 0，其餘數字與沒填時相同 |
| 一棒的高低點同時碰到止損又觸發反手信號 | 先以止損價出場（第 1 步），再依信號開新倉（第 2 步）。開倉次數 +1 |

## 6. Non-Functional Requirements

| 面向 | 要求 |
|:---|:---|
| **相容性** | 兩個距離留白時，回測回傳的**每一個既有數字逐字不變**。既有的回測測試**一條都不改**——寫在這一刀之前的斷言是「沒有東西移位」的唯一證據 |
| **正確性** | 新規則全部以數字表釘住（純算術，無 I/O、無時鐘） |
| **效能** | 每一棒多一次高低點比較。同一個走訪，不多一圈 |
| **精度** | 價格與金額一律精確小數；距離也是（它要乘進價格） |
| **可測性** | 模擬層仍然是「K 線進、意見進、成績單出」的純函式 |

## 7. Dependencies & Risks

| 項目 | 說明 | 處置 |
|:---|:---|:---|
| **依賴** 部位模型 | 出場價位掛在它身上（與單位數同一個位置） | 建構時算一次 |
| **依賴** 距離檢查措辭 | 與機器人那一側共用一份 | 直接沿用既有的檢查函式，不複製 |
| **風險** 做多做空方向寫反 | 錯的價位仍然是一個看起來合理的價格——**看不出來** | 四個方向各一個數字案例；沿用既有那個「往哪一邊」的算式，不重寫 |
| **風險** 「進場那一棒不檢查」被實作成一個比對 | 一個比對會在時區、在同一秒開盤的兩棒上出錯 | **用順序表達，不用比對**：第 1 步在第 2 步之前 |
| **風險** 既有成績單悄悄改變 | 這一刀最不可接受的結果 | 留白＝零值＝不觸發；既有測試一條都不改就必須全綠 |
| **風險** 三個專案的措辭漂移 | 同一個 150 得到兩句話 | 前後端各自沿用自己那一份既有的距離檢查（它們上一刀已經對齊過） |

## 8. Appendix

### 新增業務詞彙（需補進 `.sdd/UL-MAP.md`）

| 詞彙 | 識別字 | 定義 |
|:---|:---|:---|
| 止損距離（回測的） | `stopLossPercentage` | 重演時止損價離**進場價**幾個百分點。零＝不模擬止損 |
| 止盈距離（回測的） | `takeProfitPercentage` | 重演時止盈價離**進場價**幾個百分點。零＝不模擬止盈 |
| 出場價位 | `exitLevels` | 上面那兩個距離合起來的那一組（也是拒絕指向的欄位名） |
| 出場原因 | `exitReason` | 一筆已平倉交易是怎麼結束的：`signal` / `stopLoss` / `takeProfit` |
| 止損出場筆數 | `stopLossExitCount` | 成績單上被止損掃出場的筆數 |
| 止盈出場筆數 | `takeProfitExitCount` | 成績單上被止盈帶走的筆數 |

**與機器人那一組同名詞刻意不共用**——UL-MAP 要寫明這個區別：

| | 機器人的 | 回測的 |
|:---|:---|:---|
| 說的是 | 每一輪**要建議什麼** | 這一次重演**怎麼模擬** |
| 從哪裡量 | 參考價（最新收盤） | **進場價** |
| 存在哪裡 | 機器人身上（存下來） | **跟著這一次呼叫走**（不存） |
| 誰填 | 機器人的主人，填一次 | 調校者，每次重演都可以換 |

### 沿用的既有詞彙

倉位方向、已平倉交易、交易模式、目標倉位、部位大小模式、初始資金、彙總刻度。
