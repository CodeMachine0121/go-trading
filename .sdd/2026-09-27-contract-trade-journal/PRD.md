# Product Requirements Document (PRD)

**Status:** Draft · **Version:** v1.0 · **Owner:** James Hsueh
**Stakeholders:** 交易服務、操作台（`go-trading-frontend` 同名切片）、外掛（`go-trading-mcp` 同名切片）

---

## 1. Background & Goal

- **Problem Statement:** 策略機器人不下單、不代操，只把信號送到擁有者的 Telegram；之後發生的事系統完全不知道——
  使用者照做了沒有、實際成交在哪、付了多少手續費與資金費、最後賺還是賠。策略的成績因此永遠只有回測那一份（樣本內），
  實盤的樣本外證據只存在使用者腦袋與交易所裡；合約機器人的建議部位也還不含手續費與滑點，沒有任何實際數字可以校正它。
- **Expected Outcome:**
  - 使用者能在一本**合約交易日誌**裡**手動**記下每一筆自己下的永續合約交易：多進多出的**成交**、**進場計畫**、**附註**、**檢討**、**標籤**。
  - 使用者只記事實，系統算出**損益、R 倍數、資金費用、最大不利／最大有利浮動、利潤捕捉率、進場滑點、浮動損益與預估強平價**。
  - 使用者能看**績效統計**與同一份合約交易策略的**實盤 vs 回測**對照。
  - 合約機器人有建議部位的訊息附上**記到交易日誌連結**，打開後預填那一輪的建議；**按下儲存之前不建立任何東西**。
  - 成功指標：使用者連續兩週每一筆實單都有記在日誌裡。
- **Out of Scope:**
  - 現貨（加密貨幣現貨、台股）交易日誌——之後另開一條線。
  - 從交易所匯入成交；系統代為下單。
  - 機器人信號自動建立交易紀錄；記錄略過的信號、「若照做會怎樣」的試算。
  - 系統內建的行情對話助手讀取或分析日誌。
  - 全倉保證金；一筆交易內反手。

---

## 2. User Personas

- **Primary Role:** 系統的使用者（交易紀錄的擁有者）。每週在交易所手動下好幾筆永續合約單。
- **Usage Context:**
  - **下單後幾分鐘內**：手機上收到機器人訊息 → 到交易所下單 → 點訊息裡的連結或打開操作台記一筆，或在 Claude Code 裡用說的記。
  - **持倉期間**：加碼、減碼時補成交；看浮動損益與預估強平價。
  - **平倉後／週末**：集中寫檢討、看統計、看實盤 vs 回測。

## 3. User Stories & Acceptance Criteria

以下若無特別說明：BTCUSDT 是系統認得的合約標的；使用者掛單費率 0.02%、吃單費率 0.05%；數字以 USDT 表示。

### US-01 — 記一筆合約交易 [P0]
**As a** 使用者, **I want** 把一筆剛在交易所下的永續合約單記進日誌, **so that** 系統開始替我追蹤它。

```gherkin
Scenario: 新增一筆做多交易
  When 使用者新增一筆交易：BTCUSDT、做多、10 倍、第一筆進場 97,905 × 0.030
  Then 這筆交易建立成功，狀態為「持倉中」
  And 它屬於新增的那一位使用者

Scenario: 沒有附進場成交
  When 使用者新增一筆交易但沒有附任何進場成交
  Then 新增被拒絕，說明一筆交易至少要有一筆進場成交

Scenario: 不認得的合約標的
  Given 「ABCUSDT」不是系統認得的合約標的
  When 使用者新增一筆 ABCUSDT 的交易
  Then 新增被拒絕，說明找不到這個合約標的

Scenario: 槓桿留白即一倍
  When 使用者新增一筆交易、槓桿倍數留白
  Then 這筆交易的槓桿倍數為一倍

Scenario: 槓桿小於一
  When 使用者新增一筆交易、槓桿倍數 0.5
  Then 新增被拒絕，說明槓桿倍數不得小於一

Scenario: 方向只有做多與做空
  When 使用者新增一筆交易、方向填「平多」
  Then 新增被拒絕，說明方向只有做多與做空

Scenario: 別人的交易一律找不到
  Given 交易 #27 屬於另一位使用者
  When 使用者查看、修改或刪除 #27
  Then 回覆「找不到這筆交易」

Scenario: 同一標的同一方向已有持倉中
  Given 使用者已有 #27 BTCUSDT 做多、持倉中
  When 使用者再新增一筆 BTCUSDT 做多
  Then 新增被拒絕，說明 BTCUSDT 做多已有持倉中的 #27，請在那一筆加成交

Scenario: 方向不同可以並存
  Given 使用者已有 BTCUSDT 做多、持倉中
  When 使用者新增一筆 BTCUSDT 做空
  Then 新增成功

Scenario: 前一筆已平倉可以再新增
  Given 使用者的 BTCUSDT 做多那一筆已平倉
  When 使用者再新增一筆 BTCUSDT 做多
  Then 新增成功
```

### US-02 — 多進多出的成交 [P0]
**As a** 使用者, **I want** 分批加碼、分批平倉都記得下, **so that** 日誌和我在交易所的實際持倉一致。

```gherkin
Scenario: 加碼後重算均價
  Given 一筆做多交易已進場 0.030 @ 97,905
  When 使用者加一筆進場成交 0.021 @ 97,960
  Then 持倉為 0.051，進場均價為 97,927.6

Scenario: 部分出場
  Given 持倉 0.051
  When 使用者加一筆出場成交 0.020
  Then 狀態仍為「持倉中」，持倉剩 0.031

Scenario: 出場正好歸零即平倉
  Given 持倉 0.031
  When 使用者加一筆出場成交 0.031
  Then 持倉為 0，狀態變成「已平倉」

Scenario: 出場超過持倉等於反手
  Given 持倉 0.031
  When 使用者加一筆出場成交 0.050
  Then 被拒絕，說明出場數量超過目前持倉 0.031，要反手請先平倉再新增一筆反方向的交易

Scenario: 已平倉不得再加成交
  Given 一筆已平倉的交易
  When 使用者加任何一筆成交
  Then 被拒絕，說明這筆交易已經平倉

Scenario: 成交價與數量必須大於零
  When 使用者記一筆成交價或數量為零或負數的成交
  Then 被拒絕，說明成交價與數量必須大於零

Scenario: 成交時間不得在未來
  Given 現在是 09-27 10:00
  When 使用者記一筆成交時間為 09-27 12:00 的成交
  Then 被拒絕，說明成交時間不能在未來

Scenario: 出場不得早於第一筆進場
  Given 第一筆進場在 09-25 14:03
  When 使用者記一筆 09-25 13:00 的出場成交
  Then 被拒絕，說明出場不能早於第一筆進場

Scenario: 持倉中可以修正打錯的成交
  Given 持倉中，一筆進場成交誤記為 97,095
  When 使用者把它改成 97,905
  Then 進場均價依修正後的成交重算

Scenario: 不得刪到沒有進場成交
  Given 持倉中，只有一筆進場成交
  When 使用者刪除這一筆成交
  Then 被拒絕，說明一筆交易至少要有一筆進場成交；要整筆放棄請刪除交易
```

### US-03 — 手續費自動帶出 [P0]
**As a** 使用者, **I want** 設一次自己的手續費率之後每筆成交自動算好, **so that** 記一筆不必另外抄手續費。

```gherkin
Scenario: 依吃單費率自動算手續費
  Given 吃單費率 0.05%
  When 使用者記一筆吃單成交 97,905 × 0.030、沒填手續費
  Then 這筆成交的手續費為 1.47

Scenario: 手動填的手續費優先
  Given 吃單費率 0.05%
  When 使用者記一筆吃單成交 97,905 × 0.030、手續費填 1.20
  Then 這筆成交的手續費為 1.20

Scenario: 尚未設定費率
  Given 使用者還沒設定任何手續費率
  When 使用者記一筆成交、沒填手續費
  Then 這筆成交的手續費為 0，並標示「未設定費率」

Scenario: 費率不得為負
  When 使用者把吃單費率設為 −0.01%
  Then 被拒絕，說明手續費率不得為負

Scenario: 改費率不回頭改舊成交
  Given 一筆已記下、手續費 1.47 的成交
  When 使用者把吃單費率改成 0.04%
  Then 那一筆成交的手續費仍為 1.47
```

### US-04 — 進場計畫、鎖定與附註 [P0]
**As a** 使用者, **I want** 進場時寫下的計畫在平倉後改不了, **so that** 回頭看到的是當時的自己，不是事後修飾過的版本。

```gherkin
Scenario: 持倉中可以修改計畫
  Given 一筆持倉中的交易
  When 使用者修改計畫止損、計畫止盈、進場理由與信心
  Then 修改成功

Scenario: 平倉後計畫鎖定
  Given 一筆已平倉的交易
  When 使用者修改計畫止損
  Then 被拒絕，說明平倉後計畫已鎖定，可以加附註

Scenario: 平倉後成交也鎖定
  Given 一筆已平倉的交易
  When 使用者修改其中一筆成交
  Then 被拒絕，說明平倉後成交已鎖定，可以加附註或刪除整筆重記

Scenario: 附註不動原本的計畫
  Given 一筆已平倉、計畫止損 96,380 的交易
  When 使用者加一則附註「止損其實是 96,300，當時打錯」
  Then 附註加上，計畫止損仍為 96,380

Scenario: 做多止損放錯邊
  Given 做多、第一筆進場 97,905
  When 使用者把計畫止損設為 98,000
  Then 被拒絕，說明做多的止損必須低於進場價

Scenario: 做空止損放錯邊
  Given 做空、第一筆進場 3,500
  When 使用者把計畫止損設為 3,450
  Then 被拒絕，說明做空的止損必須高於進場價

Scenario: 止盈放錯邊
  Given 做多、第一筆進場 97,905
  When 使用者把計畫止盈設為 97,000
  Then 被拒絕，說明做多的止盈必須高於進場價

Scenario: 信心超出範圍
  When 使用者把信心設為 6
  Then 被拒絕，說明信心只能是 1 到 5
```

### US-05 — 看一筆交易的結果 [P0]
**As a** 使用者, **I want** 不必自己算就看到這筆交易賺賠多少、承擔了多少風險, **so that** 我可以誠實地評估它。

```gherkin
Scenario: 平倉後的損益與 R 倍數
  Given 做多 0.051，進場均價 97,927.6、出場均價 100,420
  And 手續費合計 5.06、資金費用付出 1.52、計畫止損 96,380
  When 使用者查看這筆交易
  Then 毛損益 +127.11、淨損益 +120.53、計畫風險 78.93、R 倍數 +1.53

Scenario: 做空的損益方向
  Given 做空 1，進場 3,500、出場 3,550
  When 使用者查看這筆交易
  Then 毛損益 −50

Scenario: 沒有計畫止損就算不出 R
  Given 一筆已平倉、沒有計畫止損的交易
  When 使用者查看這筆交易
  Then 損益照常呈現，R 倍數顯示「未設止損，算不出」

Scenario: 做多付資金費
  Given 做多，持倉期間結算 3 次、每次費率 +0.01%、名目約 5,050
  When 使用者查看這筆交易
  Then 資金費用為付出 1.52

Scenario: 做空收資金費
  Given 做空，持倉期間結算 3 次、每次費率 +0.01%、名目約 5,050
  When 使用者查看這筆交易
  Then 資金費用為收到 1.52

Scenario: 沒跨過結算
  Given 持倉期間沒有跨過任何資金費率結算時間
  When 使用者查看這筆交易
  Then 資金費用為 0

Scenario: 沒有結算資料
  Given 持倉期間系統沒有這個標的的資金費率結算紀錄
  When 使用者查看這筆交易
  Then 資金費用顯示「沒有結算資料，無法計算」，淨損益標示未含資金費用

Scenario: 最大不利、最大有利與利潤捕捉率
  Given 做多 0.051、進場均價 97,927.6、計畫風險 78.93、毛損益 +127.11
  And 持倉期間合約行情最低 97,110、最高 100,960
  When 使用者查看這筆交易
  Then 最大不利 −0.53R、最大有利 +1.96R、利潤捕捉率 82%

Scenario: 持倉中的最大不利與最大有利算到目前為止
  Given 一筆持倉中的交易
  When 使用者查看這筆交易
  Then 最大不利與最大有利以第一筆進場到最新一根合約行情為範圍

Scenario: 沒有行情就算不出最大不利與最大有利
  Given 持倉期間系統沒有這個標的的合約行情
  When 使用者查看這筆交易
  Then 最大不利、最大有利、利潤捕捉率顯示「沒有行情資料，無法計算」

Scenario: 持倉中的浮動損益
  Given 做多持倉 0.051、進場均價 97,927.6
  And 最新一根一分鐘合約 K 線收盤 98,500
  When 使用者查看這筆交易
  Then 浮動毛損益 +29.19，並標示為以最新價估算

Scenario: 沒有最新價就不估浮動損益
  Given 一筆持倉中的交易，系統沒有這個標的的合約行情
  When 使用者查看這筆交易
  Then 浮動損益顯示「沒有最新價，無法估算」

Scenario: 持倉中的預估強平價
  Given 一筆持倉中的交易，這個標的有交易規格
  When 使用者查看這筆交易
  Then 呈現以目前進場均價、持倉與槓桿倍數，照合約機器人同一套公式算出的預估強平價，並標示為估算

Scenario: 沒有交易規格就估不出強平價
  Given 一筆持倉中的交易，這個標的還沒有交易規格
  When 使用者查看這筆交易
  Then 預估強平價顯示「還沒有交易規格，估不出」
```

### US-06 — 列出與刪除交易 [P0]
**As a** 使用者, **I want** 一眼看到我所有的交易並刪掉記錯的, **so that** 日誌保持乾淨。

```gherkin
Scenario: 列出自己的交易
  Given 使用者有 3 筆交易，另一位使用者有 2 筆
  When 使用者列出交易
  Then 只回那 3 筆，第一筆進場時間最新的排前面

Scenario: 依狀態篩選待檢討
  Given 使用者有 2 筆持倉中、4 筆已平倉未檢討、5 筆已檢討
  When 使用者只列出已平倉的交易
  Then 只回那 4 筆

Scenario: 刪除整筆交易
  Given 使用者的交易 #33 有 2 筆成交、1 則附註與檢討
  When 使用者刪除 #33
  Then #33 連同它的成交、附註、檢討一併消失

Scenario: 沒有任何交易
  Given 使用者還沒有任何交易
  When 使用者列出交易
  Then 回空清單
```

### US-07 — 關聯交易策略 [P1]
**As a** 使用者, **I want** 標註這筆是依哪一份合約交易策略做的, **so that** 之後能比較照策略做與自己判斷的成績，並拿實盤去對照回測。

```gherkin
Scenario: 指名自己的合約交易策略
  Given 使用者有自己的合約交易策略「BTC 趨勢跟隨」
  When 使用者新增交易時指名它
  Then 這筆交易關聯到「BTC 趨勢跟隨」

Scenario: 不指名即自行判斷
  When 使用者新增交易時沒有指名交易策略
  Then 這筆交易的來源為「自行判斷」

Scenario: 不能指名 K 線交易策略
  Given 「ETH 均線」是一份 K 線交易策略
  When 使用者新增交易時指名它
  Then 被拒絕，說明只能指名合約交易策略

Scenario: 不能指名別人的交易策略
  Given 「別人的策略」屬於另一位使用者
  When 使用者新增交易時指名它
  Then 被拒絕，說明找不到這份交易策略

Scenario: 關聯的策略被刪除
  Given 交易 #27 關聯到「BTC 趨勢跟隨」
  And 「BTC 趨勢跟隨」之後被刪除
  When 使用者查看 #27
  Then #27 仍在，顯示「關聯的交易策略已刪除」，來源仍算「有關聯策略」
```

### US-08 — 檢討與標籤 [P1]
**As a** 使用者, **I want** 平倉後寫檢討並貼上失誤與型態標籤, **so that** 我看得出自己反覆犯的錯。

```gherkin
Scenario: 平倉後寫檢討
  Given 一筆已平倉的交易
  When 使用者寫檢討：做對、做錯、下次怎麼做、執行評分 4
  Then 狀態變成「已檢討」

Scenario: 持倉中不能檢討
  Given 一筆持倉中的交易
  When 使用者寫檢討
  Then 被拒絕，說明平倉後才能檢討

Scenario: 執行評分超出範圍
  Given 一筆已平倉的交易
  When 使用者寫檢討、執行評分 6
  Then 被拒絕，說明執行評分只能是 1 到 5

Scenario: 已檢討仍可修改檢討
  Given 一筆已檢討的交易
  When 使用者修改檢討內容
  Then 修改成功，狀態仍為「已檢討」

Scenario: 預設失誤標籤
  Given 一位還沒動過標籤的使用者
  When 使用者列出失誤標籤
  Then 有五個：追價進場、移動止損、提早出場、部位過大、報復性交易

Scenario: 自訂型態標籤並貼上
  When 使用者建立型態標籤「突破」並貼到交易 #27
  Then #27 帶著「突破」

Scenario: 同類標籤名稱不得重複
  Given 使用者已有型態標籤「突破」
  When 使用者再建立型態標籤「突破」
  Then 被拒絕，說明已有同名的型態標籤

Scenario: 不同類可以同名
  Given 使用者已有型態標籤「突破」
  When 使用者建立失誤標籤「突破」
  Then 建立成功

Scenario: 標籤可以改名
  Given 失誤標籤「移動止損」貼在 4 筆交易上
  When 使用者把它改名為「放寬止損」
  Then 那 4 筆交易改為帶著「放寬止損」

Scenario: 使用中的標籤不能刪除
  Given 失誤標籤「移動止損」貼在 4 筆交易上
```

## 4. Business Flow & Logic

- **Flow Diagram:**

  ```mermaid
  stateDiagram-v2
    [*] --> 持倉中: 新增（附第一筆進場成交）
    持倉中 --> 持倉中: 加進場／部分出場／修正成交／修改計畫
    持倉中 --> 已平倉: 出場使持倉正好歸零
    已平倉 --> 已檢討: 寫檢討
    已檢討 --> 已檢討: 修改檢討
    持倉中 --> [*]: 刪除
    已平倉 --> [*]: 刪除
    已檢討 --> [*]: 刪除
  ```

- **Core Business Rules:**
  - **歸屬**：一筆合約交易紀錄屬於恰好一位使用者，建立當下決定、不得更換或轉讓；只有擁有者看得到、改得動、刪得掉。別人的一律「找不到」。
    手續費率、標籤同樣只屬於本人。
  - **一標的一方向一筆持倉中**：同一位使用者、同一個合約標的、同一個方向，同時最多一筆持倉中。
  - **成交**：進場或出場、成交時間、成交價、數量、掛單或吃單、手續費。價與量大於零；時間不在未來；出場不早於第一筆進場；
    出場後持倉不得為負（不能反手）；持倉正好歸零即已平倉。持倉中可修改或刪除成交（至少留一筆進場）；**已平倉後成交與計畫一起鎖定**，
    記錯只能加附註或刪除整筆重記。
  - **均價**：進場均價＝Σ(進場價 × 數量) ÷ Σ進場數量；出場均價同理。
  - **手續費**：沒填時＝成交價 × 數量 × 對應（掛單／吃單）費率；填了以填的為準；尚未設定費率時為 0 並標示「未設定費率」。
    手續費在記成交當下定下來，之後改費率不回頭改。
  - **毛損益**：做多＝（出場均價 − 進場均價）× 出場數量；做空反過來。持倉中另有**浮動毛損益**＝（最新價 − 進場均價）× 持倉（做空反過來），最新價為最後一根走完的一分鐘合約 K 線收盤價，是估算。
  - **淨損益**＝毛損益 − 手續費合計 ＋ 資金費用（付出為負、收到為正）。資金費用算不出時，淨損益照算並標示未含資金費用。
  - **資金費用**：持倉期間每一次資金費率結算，以結算當下的持倉數量 × 結算時的標記價格為名目，乘上費率；費率正做多付、做空收，負則反過來。
    結算當下沒有標記價格時以該筆交易的進場均價估名目（只發生在交易所最早期的結算）。持倉期間沒有這個標的的結算紀錄時「無法計算」（不是 0）。
  - **計畫風險**＝|進場均價 − 計畫止損| × 進場總數量；**R 倍數**＝淨損益 ÷ 計畫風險；沒有計畫止損即「算不出」。
  - **止損止盈的邊**：做多止損低於第一筆進場價、止盈高於；做空相反。
  - **最大不利／最大有利**：第一筆進場時刻到平倉時刻（持倉中則到最新一根）之間，合約行情最不利／最有利的價格，
    以進場均價與進場總數量換算成浮動損益，再除以計畫風險成為 R；**利潤捕捉率**＝毛損益 ÷ 最大有利浮動損益（最大有利不大於零時不適用）。
  - **預估強平價**：只在持倉中呈現，以進場均價、持倉、槓桿倍數（保證金＝進場均價 × 持倉 ÷ 槓桿倍數），套用合約機器人預估強平價的同一套公式與分級；是估算。
  - **計畫**：計畫止損、計畫止盈、進場理由、信心（1–5），皆選填；持倉中可改，平倉後鎖定。**附註**任何時候可新增，不可改寫原計畫。
  - **檢討**：做對、做錯、下次怎麼做、執行評分（1–5）、失誤標籤。只能在平倉後寫；第一次寫下即「已檢討」；之後仍可修改。
  - **標籤**：兩類——失誤標籤、型態標籤。每位使用者一開始就有五個預設失誤標籤（追價進場、移動止損、提早出場、部位過大、報復性交易），
    與自訂的一樣可以改名、沒在用時可以刪除。同一類內名稱不得重複（去前後空白後比對）。使用中的標籤不能刪除。
  - **關聯交易策略**：選填，只能是自己的合約交易策略。策略刪除後交易保留並標示，仍屬「有關聯策略」一組。
  - **統計**：期間選項為最近 7 天、30 天（預設）、90 天、全部；以**平倉時間**落在期間內的已平倉交易計算，持倉中不計。
    勝率＝淨損益大於零的比例（打平不算贏；0 筆時不適用）；平均 R；獲利因子＝獲利交易淨損益合計 ÷ 虧損交易淨損益合計的絕對值（沒有虧損交易時不適用）；
    累積 R 曲線依平倉時間排列；R 分布；每一種失誤標籤的 R 合計與筆數；有關聯策略 vs 自行判斷；平均進場滑點（只計來自連結的交易）；
    費用佔毛利＝（手續費合計 ＋ 付出的資金費用合計）÷ 獲利交易毛損益合計。沒有計畫止損的交易計入損益與勝率、不計入 R 相關數字，並標示排除幾筆。
  - **實盤 vs 回測**：對一份合約交易策略，按標的分組它已平倉的關聯實單；每組以第一筆進場到最後一筆出場為期間、
    以這組最後一筆實單的槓桿倍數、初始資金 10,000、全押、進出場成本率皆為使用者的吃單費率，重演一次（查看時才做，不留存）。
    並排：平倉筆數、勝率、做多勝率、做空勝率（與成績單同一定義）。實盤只計已平倉。
  - **記到交易日誌連結**：只附在合約機器人、做多或做空、而且有建議部位的那一輪訊息。連結指名「那台機器人的那一輪」，
    只有機器人擁有者讀得到它的預填內容。預填：合約標的、方向、槓桿倍數、計畫止損＝建議止損、計畫止盈＝建議止盈、關聯交易策略＝機器人引用的那一份、
    進場價＝那一輪的參考價、數量＝名目 ÷ 參考價並照數量步進往下取整。**那一輪要記得當時的參考價**，才能預填進場價與算滑點。
  - **來源快照**：從連結建立的交易，記下機器人、第幾輪、當時參考價、建議止損、建議止盈——那一輪之後會被刷掉。
  - **進場滑點**＝做多：（進場均價 − 參考價）÷ 參考價；做空：（參考價 − 進場均價）÷ 參考價。正值代表對這筆交易不利。
- **Edge Cases:**
  - 使用者從連結打開但沒儲存 → 什麼都不建立（交易服務不因「打開連結」而產生任何紀錄）。
  - 同一條連結儲存兩次 → 第二次會因「一標的一方向一筆持倉中」被擋下，或（前一筆已平倉時）建立第二筆；不另設去重。
  - 關聯的交易策略、機器人被刪除 → 交易與來源快照保留。
  - 合約標的之後被移出合約追蹤名單 → 交易不受影響，只是之後的行情可能沒有，相關數字標示無法計算。
  - 資料讀取暫時失敗 → 那一項說明暫時算不出，不以 0 代替；交易本身照常呈現。

## 6. Non-Functional Requirements

- **Performance:** 列出交易與查看單筆在一般使用量（數百筆交易）下即時回應；實盤 vs 回測需重演，允許數秒並受既有重演的時限與同時上限約束。
- **Security:** 交易紀錄、手續費率、標籤只有本人讀寫；連結本身不含任何建議內容，打開時需登入並確認是機器人擁有者。
- **Compatibility:** 沿用既有使用者登入與外掛授權；時間一律以世界標準時間留存。
- **Analytics / Tracking:** N/A

## 7. Dependencies & Risks

- **External Dependencies:** 既有的合約標的與交易規格、維持保證金分級、合約 K 線、資金費率結算、合約重演、合約機器人與執行紀錄、Telegram 投遞。
- **Known Risks:**
  - 執行紀錄目前沒記參考價；連結要能預填進場價與算滑點，執行紀錄需開始記下每一輪的參考價（舊的執行紀錄沒有，打開時進場價不預填）。
  - 使用者沒有追蹤的合約標的沒有行情，最大不利／最大有利、浮動損益與部分資金費用會算不出——這是預期行為，需在畫面清楚說明。
  - 實盤 vs 回測的重演設定（初始資金、全押、成本）是為了比「勝率」而定的固定口徑，不代表使用者的實際資金配置；並排的只有筆數與勝率類數字。
  - 資金費用以結算時的標記價格估算名目，可能與交易所實扣金額有些微差距。
