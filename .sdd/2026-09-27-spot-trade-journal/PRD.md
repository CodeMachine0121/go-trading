# Product Requirements Document (PRD)

**Status:** Draft · **Version:** v1.0 · **Owner:** James Hsueh
**Stakeholders:** 交易服務、操作台（`go-trading-frontend` 同名切片）、外掛（`go-trading-mcp` 同名切片）

---

## 1. Background & Goal

- **Problem Statement:** 合約交易日誌只收永續合約；使用者同時交易加密貨幣現貨與台股，這些交易沒有地方記。現貨只有先買後賣、沒有槓桿、沒有資金費用與強平，
  不能塞進合約日誌。另外，合約日誌目前把每一筆叫「成交」，但合約的說法是開倉、加倉、減倉、平倉；機器人訊息的記到交易日誌連結也只有合約機器人有。
- **Expected Outcome:**
  - 一本與合約分開的**現貨交易日誌**，涵蓋加密貨幣現貨與台股：記買進、賣出、計畫、附註、檢討、標籤；系統算淨損益、報酬率、R（有止損時）、最大不利／最大有利、浮動損益；
    依市場分組的統計；現貨的實盤 vs 回測。
  - 合約日誌改用開倉／加倉／減倉／平倉、開倉價／平倉價、開倉均價／平倉均價，不再說「成交」「成交價」。
  - 現貨機器人的買入與出場訊息附連結，導到現貨日誌；合約機器人的連結照舊導到合約日誌。
  - 成功指標：使用者的現貨實單（加密與台股）連續兩週都有記在現貨日誌裡。
- **Out of Scope:** 現貨手續費率自動帶出；幣別換算與跨幣別加總；現貨與合約合併成一份統計；從交易所匯入成交；代為下單；改動現貨機器人的設定、停損停利或訊息內容（只多一條連結）。

---

## 2. User Personas

- **Primary Role:** 系統的使用者（交易紀錄的擁有者），手動交易加密貨幣現貨、台股與永續合約。
- **Usage Context:** 收到現貨機器人的買入或出場訊息 → 到券商或交易所下單 → 點連結或到操作台記一筆；台股盤後集中補記；週末看依市場分組的統計與實盤 vs 回測。

## 3. User Stories & Acceptance Criteria

以下若無特別說明：2330 是系統認得的台股標的；BTCUSDT 是系統認得的加密貨幣現貨標的；數字以該市場的計價幣表示（台股新台幣、加密貨幣 USDT）。

### US-01 — 合約日誌改用開倉／平倉的說法 [P0]
**As a** 使用者, **I want** 合約日誌用合約的說法稱呼每一筆, **so that** 它讀起來就像我在交易所看到的合約倉位。

```gherkin
Scenario: 第一筆叫開倉
  Given 一筆新的 BTCUSDT 做多交易
  When 使用者記下第一筆 97,905 × 0.030
  Then 這一筆稱為「開倉」，它的價格稱為「開倉價」

Scenario: 之後同方向叫加倉
  Given 持倉 0.030
  When 使用者再記一筆同方向 0.021
  Then 這一筆稱為「加倉」

Scenario: 部分反向叫減倉
  Given 持倉 0.051
  When 使用者記一筆反向 0.020
  Then 這一筆稱為「減倉」，它的價格稱為「平倉價」

Scenario: 讓持倉歸零的叫平倉
  Given 持倉 0.031
  When 使用者記一筆反向 0.031
  Then 這一筆稱為「平倉」，這筆交易變成已平倉

Scenario: 合約交易不再出現成交價
  When 使用者看一筆合約交易
  Then 均價稱為「開倉均價」與「平倉均價」，所有說明與拒絕訊息都不出現「成交」「成交價」
```

### US-02 — 記一筆現貨交易 [P0]
**As a** 使用者, **I want** 把在券商或交易所買的現貨記進現貨日誌, **so that** 現貨的成績也有地方追蹤。

```gherkin
Scenario: 新增一筆台股交易
  When 使用者新增：買進 2330，1,000 股 @ 1,050
  Then 建立一筆持有中的現貨交易，所屬市場為台股、以新台幣計

Scenario: 新增一筆加密貨幣現貨交易
  When 使用者新增：買進 BTCUSDT 0.05 @ 97,900
  Then 建立一筆持有中的現貨交易，所屬市場為加密貨幣、以 USDT 計

Scenario: 同一標的已有持有中
  Given 使用者已有 2330 持有中的 #5
  When 使用者再新增一筆 2330
  Then 新增被拒絕，說明 2330 已有持有中的 #5，請在那一筆加買進

Scenario: 現貨沒有槓桿
  When 使用者新增一筆現貨交易並填了槓桿
  Then 新增被拒絕，說明現貨只有先買後賣、沒有槓桿

Scenario: 現貨不能先賣
  When 使用者新增一筆現貨交易，第一筆是賣出
  Then 新增被拒絕，說明現貨只有先買後賣，第一筆必須是買進

Scenario: 台股數量必須是整數股
  When 使用者買進 2330 1,000.5 股
  Then 被拒絕，說明台股數量以股計，必須是整數

Scenario: 不認得的現貨標的
  Given 「ABCXYZ」不是系統認得的現貨標的
  When 使用者新增一筆 ABCXYZ
  Then 新增被拒絕，說明找不到這個現貨標的

Scenario: 別人的現貨交易一律找不到
  Given 現貨交易 #9 屬於另一位使用者
  When 使用者查看、修改或刪除 #9
  Then 回覆「找不到這筆交易」
```

### US-03 — 分批買進與賣出 [P0]
**As a** 使用者, **I want** 分批買、分批賣都記得下, **so that** 日誌和我的實際持有一致。

```gherkin
Scenario: 部分賣出
  Given 持有 1,000 股
  When 使用者賣出 400 股
  Then 仍為持有中，剩 600 股

Scenario: 全部賣出即平倉
  Given 持有 600 股
  When 使用者賣出 600 股
  Then 這筆交易變成已平倉

Scenario: 賣出超過持有
  Given 持有 600 股
  When 使用者賣出 800 股
  Then 被拒絕，說明賣出數量超過目前持有 600

Scenario: 手續費留白即零
  When 使用者記一筆買賣、手續費留白
  Then 這一筆的手續費為 0

Scenario: 台股賣出的證交稅併入手續費
  When 使用者記一筆台股賣出、手續費填 1,983
  Then 這一筆的手續費為 1,983

Scenario: 手續費不得為負
  When 使用者記一筆買賣、手續費填 −1
  Then 被拒絕，說明手續費不得為負

Scenario: 已平倉不得再加買賣
  Given 一筆已平倉的現貨交易
  When 使用者再加一筆買進或賣出
  Then 被拒絕，說明這筆交易已經平倉
```

### US-04 — 現貨的計畫與結果 [P0]
**As a** 使用者, **I want** 不必自己算就看到現貨交易賺多少、報酬率多少, **so that** 我能誠實評估它。

```gherkin
Scenario: 平倉後的損益、報酬率與 R
  Given 買進均價 1,050、1,000 股；賣出均價 1,120；手續費合計 2,100；計畫止損 1,000
  When 使用者查看這筆交易
  Then 淨損益 +67,900、報酬率 +6.47%、R 倍數 +1.36

Scenario: 沒有計畫止損
  Given 一筆已平倉、沒有計畫止損的現貨交易
  When 使用者查看這筆交易
  Then 報酬率照常呈現，R 倍數顯示「未設止損，算不出」

Scenario: 止損放錯邊
  Given 第一筆買進 1,050
  When 使用者把計畫止損設為 1,080
  Then 被拒絕，說明止損必須低於買進價

Scenario: 平倉後計畫鎖定
  Given 一筆已平倉的現貨交易
  When 使用者修改計畫止損
  Then 被拒絕，說明平倉後計畫已鎖定，可以加附註

Scenario: 最大不利與最大有利
  Given 持有期間現貨行情最低 1,020、最高 1,150
  When 使用者查看這筆交易
  Then 呈現最大不利價 1,020、最大有利價 1,150 與各自的浮動損益

Scenario: 沒有行情就算不出最大不利與最大有利
  Given 持有期間系統沒有這個標的的現貨行情
  When 使用者查看這筆交易
  Then 最大不利與最大有利顯示「沒有行情資料，無法計算」

Scenario: 持有中的浮動損益，沒有資金費用與強平價
  Given 一筆持有中的現貨交易，最新價 1,080
  When 使用者查看這筆交易
  Then 以最新價估浮動損益，並標示為估算；結果裡沒有資金費用，也沒有預估強平價
```

### US-05 — 現貨統計 [P1]
**As a** 使用者, **I want** 依市場分開看現貨成績, **so that** 新台幣與 USDT 不會被混在一起。

```gherkin
Scenario: 依市場分組
  Given 期間內台股平倉 10 筆、加密貨幣現貨平倉 6 筆
  When 使用者看現貨統計
  Then 分成台股與加密貨幣兩組，各自呈現勝率、平均報酬率、獲利因子、累積損益，金額不跨幣別加總

Scenario: 平均 R 只用有止損的交易
  Given 期間內台股平倉 10 筆，其中 3 筆有計畫止損
  When 使用者看現貨統計
  Then 台股的平均 R 以那 3 筆計，並標示以 3 筆計

Scenario: 失誤成本只算在現貨統計
  Given 一筆現貨交易貼了「追價進場」
  When 使用者看現貨統計
  Then 現貨統計的失誤成本出現「追價進場」，合約統計不受影響

Scenario: 期間內沒有平倉的現貨交易
  Given 最近 7 天沒有任何現貨交易平倉
  When 使用者看最近 7 天的現貨統計
  Then 兩組都顯示這段期間沒有已平倉交易，勝率為不適用而不是 0%
```

### US-07 — 機器人訊息的連結依市場導向 [P1]
**As a** 使用者, **I want** 點機器人訊息的連結就進到對的那本日誌, **so that** 現貨與合約不會記錯本。

```gherkin
Scenario: 合約機器人連結導到合約日誌
  Given 合約機器人某一輪做多、有建議部位
  When 使用者點那則訊息的連結
  Then 打開合約交易日誌的新增頁，與原本相同

Scenario: 現貨機器人買入的連結預填新增
  Given 現貨機器人買入 2330：參考價 1,050、建議開倉金額 105,000、建議止損 1,000、建議止盈 1,150
  When 使用者點連結
  Then 打開現貨交易日誌的新增頁，預填 2330、買進價 1,050、數量 100 股、計畫止損 1,000、計畫止盈 1,150、關聯機器人引用的交易策略
  And 買進價與數量標示「請改成實際成交」

Scenario: 現貨機器人買入但沒有建議部位
  Given 現貨機器人買入 2330，那一輪沒有建議部位
  When 使用者點連結
  Then 預填標的與買進價，數量留空

Scenario: 現貨機器人出場，已有持有中
  Given 現貨機器人對 2330 出場，使用者已有 2330 持有中的 #5、持有 600 股
  When 使用者點連結
  Then 帶出對 #5 加一筆賣出，預填賣出價＝參考價、數量 600 股

Scenario: 現貨機器人出場，沒有持有中
  Given 現貨機器人對 2330 出場，使用者沒有 2330 持有中
  When 使用者點連結
  Then 說明沒有持有中的 2330，並提供新增一筆

Scenario: 買入時已有持有中
  Given 使用者已有 2330 持有中的 #5
  When 使用者點現貨機器人買入 2330 的連結
  Then 帶出對 #5 加一筆買進

Scenario: 別人的或已被刷掉的連結
  Given 那一輪屬於另一位使用者的現貨機器人，或已不在機器人記得的最近 50 輪
  When 使用者點連結
  Then 回覆找不到，或說明這一輪的建議已不在紀錄中，與合約相同

Scenario: 現貨機器人其他訊息一字不變
  Given 一台現貨機器人
  When 它送出買入或出場訊息
  Then 除了最後多一條記到交易日誌連結，訊息其餘內容一字不變
```

### US-08 — 現貨的實盤 vs 回測 [P2]
**As a** 使用者, **I want** 拿現貨實單去對照同一段期間的重演, **so that** 我看得出現貨策略在實盤是否偏離回測。

```gherkin
Scenario: 現貨對照
  Given 一份 K 線交易策略有 2330 的已平倉實單
  When 使用者看這份策略的現貨實盤 vs 回測
  Then 以同一段期間、2330 重演一次現貨回測，並排平倉筆數與勝率
  And 重演不計任何成本
```

## 4. Business Flow & Logic

- **Core Business Rules:**
  - **現貨交易紀錄**：交易標的、所屬市場（依標的登錄，使用者不填）、買賣、計畫、附註、檢討、標籤、狀態（持有中 → 已平倉 → 已檢討），選填關聯的 K 線交易策略與來源。
    屬於恰好一位使用者；同一位使用者、同一標的同時最多一筆持有中。與合約日誌完全獨立——同代號（如 BTCUSDT）在兩本各自記、互不影響。
  - **買賣**：買進或賣出、時間、價格、數量、手續費。價與量大於零；時間不在未來；賣出不早於第一筆買進；賣出後持有不得為負；持有正好歸零即已平倉；
    台股數量必須是整數股；第一筆必須是買進；持有中可修正或刪除（至少留一筆買進），平倉後鎖定。
  - **手續費**：每筆自己填；留白即 0；不得為負；台股證交稅併入手續費。
  - **計畫**：計畫止損低於第一筆買進價、計畫止盈高於；信心 1–5；持有中可改、平倉後鎖定；附註任何時候可加。
  - **淨損益**＝（賣出均價 − 買進均價）× 賣出數量 − 手續費合計。**買進成本**＝買進均價 × 買進總數量。**報酬率**＝淨損益 ÷ 買進成本。
  - **R 倍數**：計畫風險＝（買進均價 − 計畫止損）× 買進總數量；R＝淨損益 ÷ 計畫風險；沒有止損即算不出。
  - **最大不利／最大有利**、**浮動損益**、**利潤捕捉率**、**進場滑點**：定義與合約日誌相同（只做多），行情取現貨一分鐘 K 線。現貨沒有資金費用與強平價。
  - **現貨統計**：以平倉時間落在期間內的現貨交易計算；恆分台股、加密貨幣兩組（沒有交易的一組也列出並標示沒有已平倉交易）；每組：勝率、淨損益合計、平均報酬率、
    獲利因子、平均 R（只計有止損者並標示筆數）、累積損益曲線、報酬率分布、失誤成本（每種失誤的筆數、淨損益合計、平均報酬率）、有關聯策略 vs 自行判斷、平均進場滑點。
    期間選項沿用 7／30／90 天、全部（預設 30 天）。
  - **列出現貨交易**：自己的交易依第一筆買進時間新到舊；可依狀態、標的、市場、期間（以第一筆買進時間判定）篩選；預設 20 筆、最多 200 筆，回覆附總筆數。
  - **策略名稱**：關聯的策略讀得到就顯示名字、確定已刪除才標示已刪除；名字讀不到時不把任何交易標成已刪除。
  - **標籤**：兩本共用；刪除時現貨與合約的交易一起算有沒有還貼著。
  - **現貨實盤 vs 回測**：已平倉關聯實單依標的分組；每組以第一筆買進到最後一筆賣出為期間，初始資金 10,000、全押、**不計成本**重演一次，並排平倉筆數與勝率；
    策略已刪除或重演失敗時實盤照常呈現；另附整份策略與每組的平均進場滑點。
  - **機器人連結**：合約機器人照舊；現貨機器人在**買入與出場**時都附連結（不論有沒有建議部位）。
    - 買入預填：標的、買進價＝參考價、數量＝建議開倉金額 ÷ 參考價（台股往下取整數股、加密貨幣往下取到 8 位小數）、計畫止損與止盈＝建議止損與止盈、關聯交易策略＝機器人引用的那一份。
      已有持有中時改為對那一筆加買進。沒有建議部位時數量留空。
    - 出場預填：對持有中那一筆加賣出，賣出價＝參考價、數量＝目前全部持有；沒有持有中時說明並提供新增。
    - 合約機器人的連結打不開現貨日誌、現貨機器人的連結打不開合約日誌（說明這條連結屬於另一本日誌）。
  - **合約用語**：第一筆＝開倉；之後同方向＝加倉；部分反向＝減倉；讓持倉歸零的反向＝平倉；價格＝開倉價／平倉價；均價＝開倉均價／平倉均價。
- **Edge Cases:** 同一條連結重複儲存會被「一標的一筆持有中」擋下；台股零股（不足 1,000 股）照常記；行情讀取失敗只讓那一項算不出。

## 6. Non-Functional Requirements

- **Performance:** 與合約日誌相同；統計每個標的只讀一次行情。
- **Security:** 現貨交易只有本人讀寫；連結打開需登入且是機器人擁有者。
- **Compatibility:** 合約日誌的資料與既有請求形狀不變，只改說法。
- **Analytics / Tracking:** N/A

## 7. Dependencies & Risks

- **External Dependencies:** 既有的現貨交易標的登錄（含所屬市場）、現貨一分鐘 K 線、現貨回測、現貨機器人與執行紀錄、合約交易日誌。
- **Known Risks:** 台股行情只有觀察清單上的標的才有，沒追蹤的台股標的最大不利／最大有利與浮動損益會算不出（預期行為）；現貨回測不計成本與實盤含手續費的勝率口徑不同，需在畫面說明。
