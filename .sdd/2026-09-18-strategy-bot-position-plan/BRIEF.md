# 策略機器人的部位規劃 — Requirements Brief

## Goal

`2026-09-18-trading-strategy-trading-mode` 讓機器人的訊息講得出**動作**：
做得了空的帳戶讀到的是「做空」，不是要他自己換算的「賣出」。

但訊息只講得出**方向**，講不出**多少**。使用者在手機上讀到

> 🔴【做空】早盤突破 · BTCUSDT
> 💰 參考價 64180.5

然後要自己開計算機：我有五萬、想押一成、開三倍、停損放三個百分點——
**那四個乘法他每一次都要重算一遍，而算錯的那一次是真的會虧錢的那一次。**

更糟的是他每一次算的**都是同一組數字**。可用資金沒變、押多少的規矩沒變、
槓桿沒變、能忍多少也沒變。變的只有參考價。

這個切片讓機器人自己算完：**開倉要押多少錢、止損放哪裡、止盈放哪裡**，
直接寫在訊息裡。

## Requirements

### 一台機器人多記一組東西：部位規劃

機器人多記五樣，**整組選填**：

- **部位資金**——這台機器人每次建議部位時，拿來算的那一筆錢。
- **倉位大小模式**與它的**數值**——全押／百分比／固定金額。
  **沿用回測既有的那三種，不造第四種、也不改名。**
- **槓桿倍數**——沒填或填 1 就是不上槓桿。
- **停損距離**與**停利距離**，各自一個百分比。

**這一組為什麼在機器人身上，不在交易策略上。**
交易策略是**規則**：什麼情況算買、什麼情況算賣。
而「我有多少錢、能忍多少」不是規則——同一套規則盯 BTC 與盯台積電，
押的錢與能忍的幅度本來就不同，**那是機器的事**，與盯哪個市場、多久醒一次同一類。

### 沒填就什麼都不變

**部位資金是這一組的開關。** 沒填（或填零）就是**沒有部位規劃**——
訊息與這個切片之前**逐字相同**。

這是「現貨也看得到金額」那個決定的落點：
**不按交易模式分，按填沒填分。** 現貨機器人填了就看得到「買進 10,000」，
沒填就跟現在一樣。硬寫「現貨永遠沒有金額」是一條以後一定會被推翻的規則。

其餘四樣各自也可以不填，而不填就是不印那幾行：

- **槓桿沒填或填 1**——不印槓桿與名目部位那兩行。現貨自然就是這樣。
- **停損距離沒填**——不印止損那一行。
- **停利距離沒填**——不印止盈那一行。

### 只有「要開倉」的那一輪才有部位規劃

一輪的結論要讓手上變成什麼樣子，**交易模式已經答得出來**
（`2026-09-17-backtest-trading-mode` 的那張表）。部位規劃就掛在那個答案上：

| 交易模式 | 這一輪的結論 | 要變成 | 有部位規劃嗎 |
| :--- | :--- | :--- | :--- |
| 現貨 | 買入 | 持多 | **有**，止損在下、止盈在上 |
| 現貨 | 賣出 | **空手** | **沒有**——那是出清，沒有東西要押 |
| 多空反手 | 買入 | 持多 | **有**，止損在下、止盈在上 |
| 多空反手 | 賣出 | **持空** | **有**，止損在**上**、止盈在**下** |
| 任一 | 持有 | 不變 | 沒有 |

**做空的止損在上面**，這一條要說死：它是這一整刀最容易寫錯、
而且寫錯了看起來完全正常的地方。

### 讀不到參考價就沒有部位規劃

止損價與止盈價都是從參考價算的。讀不到價，三個數字一個都算不出來——
那一輪照現在的做法說「讀不到最新 K 線」，**不印建議部位那一段**，
也**不印一個用別的價算出來的數字**。

### 訊息長什麼樣

```
🔴【做空】早盤突破 · BTCUSDT

💰 參考價 64180.5
　　2026-09-18 01:10 UTC 那一根一分鐘 K 線的收盤價
⚙️ 交易模式 多空反手

📐 建議部位（這個系統不下單）
　・保證金 5000（部位資金 50000 的 10%）
　・槓桿 3 倍 → 名目 15000
　・止損 66105.915（往上 3%，虧 450）
　・止盈 60971.475（往下 5%，賺 750）
　⚠️ 回測沒有把止損止盈算進去

📊 各來源怎麼說
　・均線黃金交叉（1h）：賣出
　・動能背離（5m）：持有
```

**那一行警告是驗收項，不是文案。** 回測到今天為止**一概不計止損止盈**
（見 `.sdd/UL-MAP.md` 的「執行回測」）。少了那一行，
使用者會拿著一張「這套規則賺 25%」的成績單，配一個**那張成績單從來沒模擬過**的停損去跑。

### 輪次記錄要記得住那幾個數字

`strategy_bot_run_records` 加寬，存下那一輪的**開倉金額、止損價、止盈價**。
不然三天後他看不懂當時那則為什麼是那個價位——
而那期間他可能已經改過部位資金或停損距離了。

## Out of Scope

- **讓回測模擬止損止盈。** 那會**改掉每一張既有成績單的數字**，是另外一整刀。
  這一刀改的是訊息講得出什麼，不是回測算什麼——所以訊息要自己承認這件事。
- **追蹤部位。** 這個系統不下單、也不知道他到底開了沒有。
  每一輪講的都是「若現在開，建議這麼大」，不是「你現在持有多少」。
  所以沒有加倉、沒有移動停損、沒有部位總覽。
- **多台機器人共用一筆錢。** 部位資金是**每一台各自的**。
  一個真的投資組合要知道每一台現在佔用多少，而這個系統不追蹤部位。
- **停損距離由策略腳本算（ATR 那種）。** 值得做，但一支信號型腳本
  **直接回傳 `indicator.Signal` 這個型別**，不是回一包 key-value——
  要吐止損得開一種新的算式產出種類，還要回答「一份交易策略有好幾個來源，誰的止損算」。
  單獨一刀。
- **手續費與滑點。** 一概不計，與回測維持一致。
- **把部位規劃存進交易策略。** 它不是規則。這一刀的前提就是這個。

## Context / Background

- **為什麼掛在「目標倉位」上，而不是掛在「信號」上。**
  交易模式已經有一個方法在答「這一輪的意見要讓手上變成什麼樣子」
  （`TradingModeDomain.TargetFor`，回測那一刀寫的）。持多、持空、空手、不變——
  **部位規劃要的就是這個答案**：前兩個要算、後兩個不算，而方向也是它給的。
  改掛在信號上，就得在這裡重寫一次「現貨的賣出是出清」，而那句話已經有家了。

- **為什麼部位資金是開關，而不是另開一個「要不要算」的開關。**
  一個布林值可以與那幾個數字互相矛盾（說要算、但沒有錢）。
  「沒有錢就沒有東西要押」本身就是那個開關，而且不可能自我矛盾。

- **為什麼那一行「回測沒算進去」非印不可。**
  這是這一刀唯一一個**使用者不可能自己發現**的落差。
  金額算錯他會看出來；但「我的停損從來沒被回測過」——
  他手上那張成績單看起來好得很，而那張成績單模擬的是一個**沒有停損**的策略。

- **為什麼做空的止損在上面要寫成獨立驗收項。**
  它是這一刀唯一一個**寫錯了完全看不出來**的地方：
  止損 60971 在做空那一輪讀起來一樣像個價格，而它其實是止盈。
  把方向釘成兩條各自的案例（#12、#13），是唯一守得住的方法。
