## 1. Background & Goal

### Problem Statement

交易模式現在只有兩種，但它其實答了**兩個各自獨立的問題**：

| | 做得了空嗎 | 借得到錢嗎 |
| :--- | :--- | :--- |
| **現貨** | 做不了 | 借不到 |
| **多空反手** | 做得了 | 借得到 |

兩個問題各有兩種答案，卻只給了兩種模式。少的那一種是**做不了空、但借得到錢**
——也就是在合約帳戶上只做多、上一點槓桿。

**而系統對這個組合的態度目前是自相矛盾的。**

一台機器人可以引用一份**現貨**交易策略、建議 **1.8 倍**的部位，存得起來、跑得起來、
訊息照送。可是拿同一份交易策略、同一個 1.8 倍去**重演**，整份被拒絕，
理由是「現貨開不了槓桿」。

於是使用者手上有一台**正在運作、卻驗證不了**的機器人。

錯的不是任何一邊的判斷——兩邊講的都對。錯的是他只有兩種模式可挑，
而「現貨」對他的帳戶是錯的詞：他不是拿現金換東西。他挑現貨，
只因為另一個選項會讓他被反手做空。

### Expected Outcome

- 交易模式**從二選一變三選一**，新增**槓桿做多**。
- **同一份交易策略配同一個槓桿倍數，在重演與在機器人身上得到同一個答案**
  ——不再有一邊接受、另一邊拒絕的組合。
- 使用者把交易策略改成槓桿做多之後，**他線上那台機器人在做的事，他重演得出來**。
- **既有的每一份交易策略、每一張成績單、每一台機器人，數字與行為逐字不變。**

### Out of Scope

- 只做空、能借錢的模式（槓桿做多的鏡像，沒有人要）。
- 把交易模式拆成兩個各自獨立的設定（四種組合只有三種成立）。
- 自動把既有的現貨交易策略改成槓桿做多。
- 回頭作廢或停掉既有的機器人。
- 資金費率。
- 強制平倉本身的任何規矩（全部沿用，一條都不改）。
- 機器人真的去下單。

## 2. User Personas

- **Primary Role:** 交易策略的擁有者——本系統唯一的使用者，自己寫規則、自己養機器人、
  自己看成績單。他在幣安開合約帳戶，只做多，上一點槓桿。
- **Usage Context:** 坐下來調策略時在畫面上操作；也會請助手替他寫或改交易策略；
  機器人在背景每隔一段時間送一則訊息到他手機上，他照著訊息自己下單。

## 3. User Stories & Acceptance Criteria

### US-01 — 挑得到「只做多、但能借錢」這種模式 [priority: P0]

**As a** 交易策略的擁有者，
**I want** 在交易模式裡挑得到「只做多、但借得到錢」，
**so that** 我的合約多倉帳戶終於有一個對的詞可以描述它，不必挑一個我明知不對的現貨。

```gherkin
Scenario: 建立一份槓桿做多的交易策略
  Given 交易模式填「槓桿做多」
  When 存這份交易策略
  Then 存得起來，而且讀回來的交易模式是「槓桿做多」

Scenario: 現貨照舊
  Given 交易模式填「現貨」
  When 存這份交易策略
  Then 存得起來，而且讀回來的交易模式是「現貨」

Scenario: 多空反手照舊
  Given 交易模式填「多空反手」
  When 存這份交易策略
  Then 存得起來，而且讀回來的交易模式是「多空反手」

Scenario: 沒填仍然是多空反手
  Given 交易模式完全沒填
  When 存這份交易策略
  Then 存得起來，而且讀回來的交易模式是「多空反手」

Scenario: 認不得的值整份拒絕，並說出現在有三種
  Given 交易模式填一個認不得的值
  When 存這份交易策略
  Then 整份拒絕，不留下任何一份交易策略
  And 拒絕的話裡同時出現「多空反手」「現貨」「槓桿做多」三個選項

Scenario: 既有的現貨交易策略不會被自動改掉
  Given 一份在這一刀之前就存在、交易模式是「現貨」的交易策略
  When 讀它
  Then 交易模式仍然是「現貨」，沒有被改成「槓桿做多」

Scenario: 修改一份既有的交易策略成為槓桿做多
  Given 一份交易模式是「現貨」的交易策略
  When 把它的交易模式改成「槓桿做多」並存起來
  Then 存得起來，而且讀回來的交易模式是「槓桿做多」
```

### US-02 — 槓桿做多的倉位行為與現貨完全一樣 [priority: P0]

**As a** 交易策略的擁有者，
**I want** 槓桿做多在倉位上的行為與現貨一字不差，
**so that** 我換過去的時候只多了「能借錢」這一件事，不必重新理解一套進出場規矩。

```gherkin
Scenario: 空手聽到買入就開多倉
  Given 交易模式是「槓桿做多」
  And 手上空手
  When 這一棒說買入
  Then 以該棒收盤價開一個多倉

Scenario: 已是多倉再聽到買入當作沒聽到
  Given 交易模式是「槓桿做多」
  And 已持有多倉
  When 這一棒又說買入
  Then 倉位原封不動，不計為一次開倉，可用資金不變

Scenario: 持有多倉聽到賣出就平倉回現金
  Given 交易模式是「槓桿做多」
  And 持有多倉
  When 這一棒說賣出
  Then 以該棒收盤價平掉多倉，錢回到可用資金
  And 之後手上空手，沒有開出任何空倉

Scenario: 空手聽到賣出什麼都不發生
  Given 交易模式是「槓桿做多」
  And 手上空手
  When 這一棒說賣出
  Then 什麼都不發生：不開空倉、不計為一次開倉、交易明細不增加、可用資金不變

Scenario: 從頭到尾不會出現空倉
  Given 一次交易模式是「槓桿做多」的重演
  When 看整份交易明細
  Then 每一筆的方向都是做多，沒有任何一筆是做空

Scenario: 不上槓桿時，槓桿做多與現貨的成績單完全一樣
  Given 同一段歷史、同一組信號、同一筆初始資金
  And 兩次重演的槓桿倍數都留白
  When 一次用「現貨」、一次用「槓桿做多」各重演一遍
  Then 兩張成績單的每一個數字都相同
  And 兩份交易明細與兩條資金曲線也都相同
```

### US-03 — 只有借得到錢的模式才開得了槓桿 [priority: P0]

**As a** 交易策略的擁有者，
**I want** 重演在我用槓桿做多時接受槓桿倍數，在我用現貨時照樣擋下來，
**so that** 「現貨」這個詞繼續只指一件事，而我的合約多倉終於算得出真實的賺賠。

```gherkin
Scenario: 槓桿做多開得了槓桿
  Given 交易模式是「槓桿做多」
  And 槓桿倍數 3
  When 發動重演
  Then 重演跑完並交出成績單
  And 每一注的曝險是押注金額的 3 倍

Scenario: 現貨仍然開不了槓桿
  Given 交易模式是「現貨」
  And 槓桿倍數 3
  When 發動重演
  Then 整份拒絕，不交出任何成績單
  And 拒絕的話說現貨借不到錢

Scenario: 多空反手照舊開得了槓桿
  Given 交易模式是「多空反手」
  And 槓桿倍數 3
  When 發動重演
  Then 重演跑完並交出成績單

Scenario: 槓桿做多但槓桿倍數留白
  Given 交易模式是「槓桿做多」
  And 槓桿倍數留白
  When 發動重演
  Then 重演跑完並交出成績單
  And 強平出場筆數是 0

Scenario: 槓桿做多但槓桿倍數填一
  Given 交易模式是「槓桿做多」
  And 槓桿倍數 1
  When 發動重演
  Then 重演跑完並交出成績單
  And 強平出場筆數是 0

Scenario: 槓桿做多也擋小於一的槓桿
  Given 交易模式是「槓桿做多」
  And 槓桿倍數 0.5
  When 發動重演
  Then 整份拒絕，不交出任何成績單
  And 拒絕的話說槓桿倍數不得小於一
```

### US-04 — 槓桿做多被強制平倉時，算法與既有的一字不差 [priority: P0]

**As a** 交易策略的擁有者，
**I want** 槓桿做多的強制平倉沿用既有那一套，
**so that** 我看到的爆倉數字與我在多空反手上看到的是同一種東西，不必分開學。

```gherkin
Scenario: 強平價在進場價下方
  Given 交易模式是「槓桿做多」
  And 一個多倉，進場價 100、槓桿倍數 5、維持保證金率 0.5%
  When 算這一注的強制平倉價
  Then 強制平倉價是 80.5

Scenario: 價格跌到強平價就被強制出場，收回零
  Given 交易模式是「槓桿做多」
  And 一個多倉，進場價 100、押 10000、強制平倉價 80.5
  When 某一棒的最低價是 80
  Then 這一注在 80.5 被強制出場，收回 0
  And 這一筆的出場原因是強平出場

Scenario: 止損比強平近時，止損先出場
  Given 交易模式是「槓桿做多」
  And 一個多倉，進場價 100、強制平倉價 80.5、止損價 95
  When 某一棒的最低價是 80
  Then 這一注在 95 出場
  And 這一筆的出場原因是止損出場

Scenario: 成績單數得出被強平幾筆
  Given 一次交易模式是「槓桿做多」、有開槓桿的重演，其中兩注被強制出場
  When 讀成績單
  Then 強平出場筆數是 2

Scenario: 沒開槓桿就不會有強平
  Given 一次交易模式是「槓桿做多」、槓桿倍數留白的重演
  When 讀成績單
  Then 強平出場筆數是 0

Scenario: 槓桿做多沒有上方的強平價
  Given 一次交易模式是「槓桿做多」、有開槓桿的重演
  When 看每一注的強制平倉價
  Then 每一個都在該注的進場價下方，沒有任何一個在上方
```

## 4. Business Flow & Logic

### 核心業務規則

**R-1 — 交易模式是兩個獨立問題的三種合法組合**

| 交易模式 | 做得了空嗎 | 借得到錢嗎 | 賣出是什麼意思 |
| :--- | :--- | :--- | :--- |
| 多空反手 | 是 | 是 | 平掉多倉，同一棒反手開空 |
| 現貨 | 否 | **否** | 平倉回現金；空手時什麼都不發生 |
| 槓桿做多 | 否 | **是** | 平倉回現金；空手時什麼都不發生 |

第四種組合（做得了空、卻借不到錢）**不成立**：放空本來就要先借到東西才賣得出去。
所以是三個選項，不是兩個各自獨立的設定。

**R-2 — 沒填就是多空反手**（既有規則，不變）。

**R-3 — 認不得的值整份拒絕**，並說出現在有**三**種（唯一的變化是清單多一項）。

**R-4 — 「借不借得到錢」這條規則，重演與機器人共用同一個答案、同一句話。**
一份交易策略借不到錢時：重演給大於一的槓桿倍數整份拒絕；
一台引用它的機器人，建議部位給大於一的槓桿倍數整台拒絕。
兩邊的措辭一字不差。

**R-5 — 槓桿倍數留白、零或一，一律當作沒有借錢**，三種模式皆然。
此時 R-4 不適用——沒有借錢就沒有那條規則。

**R-6 — 強制平倉的每一條規矩全部沿用，一條都不新增。**
強平距離、維持保證金率的預設與上限、止損與強平誰先到、不穿倉、
成績單上的強平出場筆數——槓桿做多只是多一種**允許**它發生的模式。
因為它只有多倉，**強平價永遠在進場價下方**。

**R-7 — 機器人訊息的寫法，按「做不做得了空」與「借不借得到錢」分開決定。**

| 交易模式 | 結論的動詞 | 印交易模式那一行嗎 |
| :--- | :--- | :--- |
| 多空反手 | 做多／做空 | 印 |
| 現貨 | 買入／出場 | **不印** |
| 槓桿做多 | **買入／出場**（做不了空） | **印**（借錢開的倉，風險不同） |

「各來源怎麼說」那一段三種模式都不變，照樣寫買入／賣出／持有。

### 邊界情況

- **既有資料一律讀作它原本的樣子。** 現貨的還是現貨，沒填的還是多空反手。
  **沒有任何一份會被自動改成槓桿做多**——改掉一份交易策略的交易模式，
  等於改掉它每一張成績單的意義，那是使用者自己的決定。
- **既有的機器人不被回頭作廢。** 目前確實存在「引用現貨交易策略、建議 1.8 倍」
  這樣的機器人，而且正在跑。它照常跑、照常送訊息、不被停掉也不被刪掉。
  **R-4 只在下一次存它的時候生效**——那時使用者才會看到那句話，
  並知道他該做的是把那份交易策略改成槓桿做多。
- **執行中的機器人本來就改不動**（既有規則）：要改得先停止。
  所以使用者會先停機器人、改策略、再存機器人，這條路本來就通。
- **一份交易策略被機器人引用中時本來就改不動**（既有規則）：
  改交易模式同樣要先停掉引用它的機器人。
- **不上槓桿時，槓桿做多與現貨在數字上無法區分**——那是對的，
  兩者只差在「借不借得到錢」，沒借的時候它們本來就是同一件事。

## 6. Non-Functional Requirements

- **Performance:** 無新增要求。判斷「借不借得到錢」不涉及任何額外的外部查詢；
  機器人存檔時多讀一份它本來就指名的交易策略。
- **Security:** 無新增要求。機器人存檔時讀的那份交易策略，
  必須仍然是**該使用者自己的**——既有的擁有權規則不因為多讀一次而放寬，
  讀到別人的一律回覆「找不到」（既有措辭）。
- **Compatibility:** 既有的每一份交易策略、每一台機器人、每一次重演，
  行為與數字**逐字不變**。既有的呼叫方式不必改一個字。
- **Analytics / Tracking:** N/A

## 7. Dependencies & Risks

### External Dependencies

無。不牽涉任何外部服務。

### Known Risks

- **使用者現有的兩台機器人會在下一次被存時遭拒。**
  這不是副作用，這正是這一刀存在的理由——那兩台現在跑的東西驗證不了。
  緩解：它們在被存之前照常跑；拒絕的話本身要說得出他該怎麼做。
- **「槓桿做多」與「現貨」在不上槓桿時數字完全相同**，
  使用者可能分不出自己現在用的是哪一個。
  緩解：機器人訊息在槓桿做多下多印那一行交易模式；畫面上選項本身也看得見。
- **交易模式從二選一變三選一，會動到每一處列舉它的地方**
  （畫面選項、助手看得懂的說明、拒絕時列出的清單）。漏掉一處的症狀是
  「有一條路挑不到新模式」，而那不會報錯，只會讓人以為功能沒做。
  緩解：驗收條件在 US-07 把三條路各寫一條。
