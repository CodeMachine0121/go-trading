# Oracle — 請求節流

每一列的「預期」**只從 PRD 推導**，在任何實作存在之前寫下。
寫測試時斷言的期望值一律抄這裡，**不准從跑出來的結果回填**。

一般額度 600/分鐘、累積 120（每 0.1 秒一份，補滿 12 秒）；身分相關 10/分鐘、累積 10（每 6 秒一份，補滿 60 秒）；
跟盤每位 20、全服務 1000；內容上限 1024 KB。`T` = 第一個請求的時刻。

## E · middleware / HTTP

| # | Given | When | Then |
| :-- | :--- | :--- | :--- |
| E1 | 額度用完 | 送請求 | 429、`Retry-After: 1`、訊息「請求太頻繁，請 1 秒後再試」、handler 沒被執行 |
| E2 | 身分相關用完 | 登入 | 429、`Retry-After: 6` |
| E3 | 跟盤 20 條 | 第 21 條 | 429、訊息「同時開著的即時跟盤已達上限，請先關掉一些再開」 |
| E4 | 跟盤請求結束（handler 返回） | 再開 | 通過 |
| E5 | 內容 1024 KB 整 | 送出 | handler 讀得到全部 |
| E6 | 內容 1024 KB + 1 位元組（宣告長度） | 送出 | 413、「送入的內容太大，上限為 1024 KB」、handler 沒被執行 |
| E7 | 未宣告長度、實際超過 | handler 讀 body | 讀取失敗 |
| E8 | 沒有信任轉手；直接連線 `192.0.2.1` 帶 `X-Forwarded-For: 1.2.3.4` | 送請求 | 來源是 `192.0.2.1` |
| E9 | 信任 `10.42.0.0/16`，標頭 `CF-Connecting-IP`；連線來自 `10.42.0.9` 帶 `CF-Connecting-IP: 1.2.3.4` | 送請求 | 來源是 `1.2.3.4` |

| E11 | 預檢 `OPTIONS` | 額度用完時 | 仍然 204（不扣額度） |
| E12 | 429 回覆、有允許的來源 | 瀏覽器讀 | 帶 `Access-Control-Expose-Headers` 含 `Retry-After` |
| E13 | 串流 handler，`ReadTimeout` 很短 | 串流超過 `ReadTimeout` | 仍持續收到更新 |
| E14 | 送請求慢於 `ReadTimeout` | — | 連線被放棄 |
