**Status:** Finalized
**Version:** v1.0
**Owner:** James Hsueh
**Stakeholders:** Engineering

## 1. Background & Goal (Why & Goal)

### Problem Statement

助手寫得出一支策略腳本，卻拼不出一份交易策略——而使用者派出去的從來是後者。
於是對話一定在「剩下的請你自己去工作檯拼起來」斷掉。

更重的是：助手**看不到自己寫的東西跑起來會怎樣**。它交出算式之後就瞎了，
算式對不對、拼起來賺不賺錢，一個字都說不出口。

### Expected Outcome

- 助手多四件能做的事：**拼一份交易策略、改一份、讀一份、列出全部**，
  再加**拿歷史重演一份**。
- 加上它早就會的改腳本，它能在**一次回答之內**走完
  「拼 → 重演 → 不滿意 → 改 → 再重演」的整圈。
- 四件事一律走使用者自己按下去的同一條路，**一條規則都不放寬**；
  被擋下來時原因交回助手，由它改一改再試。
- 查詢次數上限由 8 提高到 **40**，一圈約五次，夠它跑七圈。

### Out of Scope

- **跑到達標為止的自動迭代**（背景工作、目標、每輪留存）。
- **「目標」這個領域概念**（賺多少、多久內）。
- **回測結果留存**——維持不留存。
- **助手主動送訊息**。
- **刪除交易策略**、**建立或操作策略機器人**。
- **資金曲線交給助手**。

---

## 2. User Personas

**Primary Role:** 已登入的使用者，同時是自己每一支策略腳本、每一份交易策略的擁有者。

**Usage Context:** 桌面瀏覽器的助手對話。他用講的描述想要什麼
（標的、本金、期望報酬），不想自己去工作檯拖拉條件樹。
他也不會自己讀成績單——他要助手讀完之後告訴他「行不行」。

## 3. User Stories & Acceptance Criteria

### US-01 — 助手拼得出一份交易策略 [priority: P0]

**As a** 使用者，**I want** 助手把它寫的幾支腳本直接拼成一份交易策略，
**so that** 我不必自己去工作檯把它講過的話重做一遍。

```gherkin
Scenario: 拼一份交易策略
  Given 我有兩支策略腳本
  When 我請助手用它們拼一份叫「動能追蹤」的交易策略
  Then 那一份存起來了
  And 它的擁有者是我
  And 助手覆述得出它的名稱與識別碼

Scenario: 擁有者一律是委託它的人
  Given 我請助手拼一份交易策略
  When 它送出
  Then 它沒有任何辦法指定擁有者
  And 存起來的那一份屬於我

Scenario: 名稱與自己既有的一份重複
  Given 我已經有一份叫「動能追蹤」的交易策略
  When 我請助手再拼一份同名的
  Then 助手被告知名稱重複
  And 它換一個名字再送一次,成功

Scenario: 來源指名一支我看不到的策略腳本
  Given 有一支策略腳本是別人的,而且沒有發佈到市集
  When 助手拼的那一份指名了它
  Then 助手被告知找不到那一支策略腳本
```

### US-02 — 助手改得動、讀得到、找得到 [priority: P0]

**As a** 使用者，**I want** 助手能接手處理已經存在的那幾份，
**so that** 我可以說「把上次那一份的賣出條件改鬆一點」而不必重講一遍。

```gherkin
Scenario: 改一份交易策略
  Given 我有一份交易策略
  When 我請助手把它的賣出條件改鬆一點
  Then 那一份被改掉了

Scenario: 列出我有哪幾份
  Given 我有三份交易策略
  When 我請助手看看我有哪幾份
  Then 助手唸得出三份的名稱與識別碼

Scenario: 讀一份的全部內容
  Given 我有一份交易策略
  When 我請助手先看看它現在長什麼樣
  Then 助手讀得到它的信號來源、兩棵條件樹與每個來源的參數值

Scenario: 別人的那一份讀不到
  Given 另一位使用者有一份交易策略
  When 助手指名那一份
  Then 它拿到「找不到」,與指名一份不存在的一字不差

Scenario: 有機器人在跑的時候改不動
  Given 我有一台執行中的機器人引用著那一份交易策略
  When 助手要改那一份
  Then 它被告知有哪幾台在跑
  And 它把這件事轉達給我,而不是硬改
```

### US-03 — 助手刪不掉交易策略 [priority: P0]

**As a** 使用者，**I want** 助手沒有刪除這個能力，
**so that** 拼了好幾輪才對的一整套判斷不會被一句話誤刪。

```gherkin
Scenario: 助手沒有刪除這個能力
  Given 我有一份交易策略
  When 我請助手把它刪掉
  Then 助手說它沒有這個能力
  And 系統裡不存在任何一件「刪除交易策略」可以給它做
```

### US-04 — 助手重演得了一份，而且讀得懂成績單 [priority: P0]

**As a** 使用者，**I want** 助手自己拿歷史檢查它拼出來的東西，
**so that** 它交給我的時候已經知道那份策略行不行,而不是要我自己去按回測。

```gherkin
Scenario: 重演一份交易策略
  Given 我有一份刻度一致的交易策略
  When 我請助手拿最近三十天、本金 500000、每次全押重演它
  Then 助手唸得出總報酬率、最大回撤、勝率與開倉次數

Scenario: 交易明細也讀得到
  Given 承上
  When 助手拿到結果
  Then 它讀得到每一筆進出場的時間、價格與賺賠

Scenario: 資金曲線不交給助手
  Given 承上
  When 助手拿到結果
  Then 裡面沒有資金曲線

Scenario: 交易明細有上限,超過時明講
  Given 一次重演有六百筆交易
  When 助手拿到結果
  Then 只列出最近的 50 筆
  And 它被告知總共有幾筆、以及成績單是全部算出來的

Scenario: 打架棒數一定在
  Given 一次重演裡有 180 棒買入與賣出同時成立
  When 助手拿到結果
  Then 它讀得到打架棒數是 180
  And 它指出這份交易策略幾乎沒有在做決定,而不是說它很穩

Scenario: 刻度不一致時被擋
  Given 我的交易策略一個來源吃一小時、一個吃五分鐘
  When 助手要重演它
  Then 它被告知刻度不一致,以及現在有哪幾種
  And 它回頭把它們調成一樣再送一次

Scenario: 別人的那一份重演不了
  Given 另一位使用者有一份交易策略
  When 助手指名那一份來重演
  Then 它拿到「找不到」
```

### US-05 — 被規則擋下來時助手改一改再試 [priority: P0]

**As a** 使用者，**I want** 助手自己處理掉那些它看得懂的錯誤，
**so that** 我不必去讀「代號 C 沒有宣告」然後做它本來就會做的事。

```gherkin
Scenario: 條件指到沒宣告的代號
  Given 助手拼的那一份,買入條件指到一個沒有宣告的來源代號 C
  When 它送出
  Then 它被告知代號 C 沒有宣告
  And 整次回答沒有被打斷
  And 它補上來源 C 之後再送一次,成功

Scenario: 參數值帶了沒宣告的名稱
  Given 助手給的參數值裡有那支腳本沒宣告的參數名稱
  When 它送出
  Then 它被告知是哪一個參數
  And 它拿掉之後再送一次,成功

Scenario: 一直被擋直到查詢次數用完
  Given 助手連試了好幾次都被擋下來
  When 查詢次數用完
  Then 它回答目前為止的進展並說明已達上限
  And 那次回答照常留存
```

### US-06 — 一次回答跑得完好幾圈 [priority: P0]

**As a** 使用者，**I want** 送出一句就讓助手自己來回改到它滿意，
**so that** 我不必一輪一輪地催它。

```gherkin
Scenario: 一句話跑完好幾圈
  Given 我說「幫我弄一份,報酬率要 10% 以上」
  When 助手拼一份、重演、不滿意、改參數、再重演
  Then 這些都發生在同一次回答裡
  And 我只送出了一句

Scenario: 查詢次數上限是四十
  Given 助手已經用掉四十次查詢
  When 它還想再重演一次
  Then 不再放行
  And 它交出目前最好的那一組並說明已達上限
```

## 4. Business Flow & Logic

### 一次「拼出來並自己檢查」的對話

```
使用者一句話
  └─ 助手（一次回答，最多 40 次查詢）
       ├─ 列出交易標的 / 看行情          （既有）
       ├─ 存幾支策略腳本                 （既有）
       ├─ 拼一份交易策略                 【新】
       ├─ 重演那一份                     【新】
       ├─ 讀成績單 → 不滿意
       ├─ 改腳本                         （既有）
       ├─ 改那一份的參數值               【新】
       ├─ 再重演                         【新】
       └─ 講出它試過什麼、選了哪一組、為什麼
```

### Core Business Rules

| # | Rule |
|---|------|
| BR-1 | 四件新能力一律走使用者自己那條路（同一個 Application），**一條規則都不放寬** |
| BR-2 | 擁有者永遠是委託助手的那個人；助手沒有欄位可以指定它 |
| BR-3 | 刪除交易策略**不存在**——不是擋下來，是沒有這件事可以做 |
| BR-4 | 規則的拒絕**交回助手當作理由**，不中斷整次回答 |
| BR-5 | 交回助手的回測結果含成績單與交易明細，**不含資金曲線**；交易明細**最多 50 筆**（取最近的），超過時明講筆數。成績單裡的數字一律是全部交易算出來的 |
| BR-6 | 打架棒數必須在交回助手的成績單裡 |
| BR-7 | 查詢次數上限的**行為不變**，只把預設值由 8 改成 40 |

### 為什麼是四隻小手而不是一隻「幫我做完」

一隻大的「照需求生出一份交易策略」會把「拼什麼」與「怎麼拼」一起鎖進一個參數表，
而那正是助手該自己想的部分。四隻小的各自對應使用者按得到的一個動作，
組合是助手的事——也因此每一隻都走使用者那條路，沒有第二套規則要維護。

### Edge Cases

| 情境 | 行為 |
|------|------|
| 助手送來的參數不是合法 JSON | 交回「參數不是合法的 JSON」當理由，它重送 |
| 助手拼的那一份一個信號來源都沒有 | 既有規則拒絕，理由交回 |
| 助手指名一份不存在的交易策略來改 | 「找不到」，與別人的一字不差 |
| 重演那一段湊不出兩根 K 線 | 既有規則拒絕，理由交回 |
| 重演的本金不是正數 | 既有規則拒絕，理由交回 |
| 助手在同一次回答裡拼了兩份同名的 | 第二份被名稱重複擋下，理由交回 |

## 5. UI/UX Design & Interaction

本切片**不動任何畫面**。助手多出來的能力經由對話呈現，
使用者看到的是助手講得出成績單、並且說「我已經幫你存好了」。

前端唯一相關的變化在另一個切片：一次回答變長之後要看得到它還在跑。

---

## 6. Non-Functional Requirements

- 一次回答最多 40 次查詢；每次重演都要跑完整段歷史，**一次回答可能數分鐘**。
  這正是「一次回答在寫的時候就看得見」那個切片存在的理由。
- 查詢次數上限維持環境變數可調，且必須大於零。
- 助手拿到的回測結果要**能讀**：純文字、欄位有名字、數字不是一長串未標示的陣列。

## 7. Dependencies & Risks

| 項目 | 說明 |
|------|------|
| 依賴 | 交易策略的建立／修改／讀取／列出（既有）、交易策略回測（既有） |
| 依賴 | 助手查詢機制 `IAssistantQuery`（既有） |
| 風險 | 40 次查詢若全用在重演上會很慢。它是環境變數，跑過再調 |
| 風險 | 一次能力交回的東西會在**之後每一輪**被重送給助手。回測結果因此比別的更需要上限——重演四五次，累積起來會在查詢次數用完之前先把它能看的東西佔滿。以交易明細上限 50 筆緩解 |
| 風險 | 助手可能拼出「幾乎全在打架」的策略而不自知。以打架棒數必須交回它來緩解 |
