**Owner:** James Hsueh
**Stakeholders:** Engineering

## 1. Background & Goal

### Problem Statement

重演一段行情時，系統只會算「押多少，就承擔多少」。押一萬塊、價格漲一成，就是賺一千。

這是現貨的算法。但**多空反手**這個交易模式本來就是寫給做得了空的帳戶用的，
而那種帳戶幾乎都能開槓桿。於是使用者拿著成績單去實際操作，兩件事對不上：

1. **賺賠差了槓桿倍數那麼多。** 成績單說賺一成，他實際賺五成；說賠一成，他實際賠五成。
2. **他會在中途被強制出場，而成績單完全不知道有這回事。**
   五倍槓桿的一注，價格逆著走大約兩成，交易所就把它平掉、押下去的錢全沒了。
   成績單裡那一注還好端端地撐著，一路撐到訊號叫它出場。

第 2 件遠比第 1 件危險。第 1 件是數字錯了，看得出來。
第 2 件是**帳戶早就歸零、後面那幾十筆交易根本不存在**，而成績單照樣把它們算進
報酬率裡，最後交出一張看起來完全合理的表。**它不會出錯、不會中斷，只會說謊。**

### Expected Outcome

- 一次重演可以說出**槓桿倍數**與**維持保證金率**。
- 開了槓桿的重演，賺賠照**曝險金額**算，並在價格走到撐不住的地方時**如實把那一注打掉**。
- 成績單與交易明細講得出**有幾注是被強制平倉打掉的**、**哪幾注**。
- **沒說槓桿的每一次重演，每一個數字與這一刀之前逐字相同。**

### Out of Scope

- **資金費率**——永續合約每隔幾小時要付或收的那筆錢。它是慢性失血，不會讓使用者
  看到假數字，所以排在後面，不在這一刀。
- **逐倉與全倉的差別**——這一版同一時間只有一注，沒有第二注可以被拖下水。
- **分批強平**——真實市場有時只平掉一部分；這一版一注就是一注，全平。
- **機器人的建議部位**——它早有槓桿倍數這個設定，但那是「每一輪建議押多少」，
  與這裡的「這一次怎麼模擬」同名不同事，兩邊刻意不共用。
- **一次掃很多交易標的**——另一件事。
- **任何留存**——這兩個新設定跟著這一次呼叫走，重演結果照樣不留存。

## 2. User Personas

- **Primary Role:** 系統的使用者本人——自己寫策略腳本或拼交易策略，
  拿歷史行情重演來決定要不要真的照它下單的人。
- **Secondary Role:** 行情對話助手——替使用者發動重演、讀成績單、再調整設定的那一圈工作，
  它說得出的設定必須與使用者自己能說的一字不差。
- **Usage Context:** 坐在畫面前一次一次調參數：換一個標的、換一段期間、換一組停損、
  換一個槓桿，比較成績單。每一次都是一問一答，結果不留存。

### US-07 — 成績單講得出強平 [priority: P1]

**As a** 系統的使用者，**I want** 成績單與交易明細講出有幾注、哪幾注是被強制平倉打掉的，
**so that** 我分得出「被停損救下來」與「押到歸零過三次」這兩張長得很像的成績單。

> **一次重演裡的逆向出場只會有一種。** 止損距離與強平距離在一次重演裡都是常數，
> 所以「哪一個近」對每一注都一樣——這不是實作的限制，現實也是如此：
> 5 倍槓桿配 5% 停損就是永遠不會爆，配 30% 停損就是永遠輪不到停損。
> 所以下面兩個情境是同一件事的兩面，不會有一次重演同時數出兩種。

```gherkin
Scenario: 被強平的那一次，成績單算在強平那一格
  Given 一次開了槓桿、沒有設止損的重演，其中一注被強制出場
  When 讀這一次的成績單
  Then 強平出場筆數是 1
  And 止損出場筆數是 0

Scenario: 被止損救下來的那一次，成績單算在止損那一格
  Given 一次開了槓桿、止損比強平近的重演，其中一注被止損掃出場
  When 讀這一次的成績單
  Then 止損出場筆數是 1
  And 強平出場筆數是 0

Scenario: 沒開槓桿的重演強平筆數恆為零
  Given 一次沒有說槓桿倍數的重演
  When 讀這一次的成績單
  Then 強平出場筆數是 0

Scenario: 交易明細指得出是哪一筆
  Given 一注被強制出場
  When 讀這一次的交易明細
  Then 那一筆的出場原因寫著強平出場
```

## 4. Business Flow & Logic

### Core Business Rules

**R1 — 槓桿的開關**
槓桿倍數留白、零或一，一律當作**沒有槓桿**：曝險金額等於押注金額，不模擬強制平倉，
維持保證金率填了也不算。判準不是「一倍很少爆」，而是**一倍沒有借錢**——
沒有債主，就沒有人會來平這一注。

**R2 — 曝險金額**
`曝險金額 ＝ 押注金額 × 槓桿倍數`。
可用資金扣的仍然只有押注金額（保證金）；賺賠、進場成本、出場成本都照曝險金額算。

**R3 — 強平距離**
`強平距離 ＝ (1 ÷ 槓桿倍數) − 維持保證金率`，是一個離**進場價**的百分比。
它是**算出來的**，不是使用者填的。

**R4 — 強制平倉價**
多倉在進場價下方、空倉在上方（與止損同一邊，也就是價格逆著這一注走的方向）。
**開倉當下就算好，之後不再變動**——與止損價、止盈價同一個理由。

**R5 — 誰先到**
止損與強平**在同一邊**，所以**離進場價近的那個一定先被碰到**。這不是猜的，是幾何。
止盈在另一邊，順序說不準，維持既有規則：先問逆向那一側（止損或強平），再問止盈。

**R6 — 不穿倉，而且只管借來的那種**
**借了錢的那一注**賠掉的錢不會超過押下去的保證金：被強制出場時收回**零**，
價格跳空崩穿也一樣（出場價就是強制平倉價）。止損比強平近、而出場成本又吃掉
剩下那點保證金時，**出場成本收到那一注還剩多少為止**，那一注一樣歸零——
這樣成績單上的現金與那一筆交易自己講的損益永遠一致。

**沒有借錢的那一注不在這條規則之內。** 一注放空在三倍的價格買回來，
確實賠得比押下去的多，而這一刀之前的每一張成績單都是這樣說的。
替它補一個地板等於在沒有人動手的情況下，把那些成績單往好看的方向改寫一遍。

**R7 — 可押上限**
`可押上限 ＝ 可用資金 ÷ (1 + 槓桿倍數 × 進場成本率)`。
沒開槓桿時分母退回 `(1 + 進場成本率)`，既有算式一個字都沒變。

**R8 — 逐字相容**
沒說槓桿倍數的每一次重演，成績單、資金曲線、交易明細的每一個數字，
都必須與這一刀之前**逐字相同**。這是每一條規則的上位約束。

### State Transitions

一注在重演中的結局從三種變成四種：
**訊號出場**、**止損出場**、**止盈出場**、**強平出場**。

### Edge Cases

| 情況 | 行為 |
| :--- | :--- |
| 交易模式是現貨、又給了大於一的槓桿倍數 | 整份拒絕，說現貨開不了槓桿 |
| 槓桿倍數小於一 | 整份拒絕，說不得小於 1 倍 |
| 維持保證金率大到強平距離不為正 | 整份拒絕，並說出這個槓桿下最多能填多少 |
| 一根 K 線同時碰到止損與強平 | 比距離，近的先 |
| 一根 K 線同時碰到逆向出場與止盈 | 逆向那一側先算（既有規則不動） |
| 跳空穿過強制平倉價 | 仍在強制平倉價出場，收回零 |
| 借了錢，止損比強平近，而出場成本大於剩下的保證金 | 出場成本收到剩多少為止，那一注歸零；交易明細的損益同步寫成賠光保證金 |
| 沒有借錢，一注賠得比押下去的多（放空被軋） | **照實記負的**，與這一刀之前逐字相同 |
| 開倉當下付不起放大後的進場成本 | 跳過這次開倉，不算失敗、不中斷、不計為一次開倉 |
| 沒說槓桿、卻說了維持保證金率 | 接受，且完全不影響結果 |

## 5. UI/UX Design & Interaction

本切片是後端行為，畫面另案處理。對畫面的唯一約束：

- 槓桿倍數與維持保證金率是**併排填的一組**，拒絕時被指出來要改的是這一組，
  由句子本身說出是哪一格——與止損／止盈那一組、進場／出場成本率那一組同一個做法。
- **強平距離不出現在成績單上**（成績單講的是發生過什麼，不是設定了什麼），
  但維持保證金率被拒絕時，句子要說出這個槓桿下最多能填到多少——
  被擋下來的人要知道該改成什麼，而不是自己一個個試。

## 6. Non-Functional Requirements

- **效能：** 強平價與止損、止盈價一樣，開倉當下算一次就固定，不在每一根 K 線上重算。
  逐棒的判斷只是幾次比大小，對一次重演的耗時沒有可觀察的影響。
- **相容性（最重要的一條）：** 沒說槓桿倍數的每一次重演，輸出逐字不變。
- **精確度：** 所有金額與價格沿用系統既有的精確小數規則，不使用浮點數。
- **安全性：** 無新增。這兩個設定不留存、不跨使用者。

## 7. Dependencies & Risks

### Dependencies

- 依賴既有的**出場價位**（止損／止盈距離）——強平必須與止損比距離。
- 依賴既有的**交易成本**——成本的計算基準從押注金額改成曝險金額。
- 依賴既有的**倉位大小模式**——可押上限的算式要把槓桿算進去。

### Risks

| 風險 | 說明 | 緩解 |
| :--- | :--- | :--- |
| 既有成績單被無聲改動 | 成本基準與可押上限的算式都動到了，一個沒顧好就會改掉所有舊重演的數字 | 每一條規則都要有「沒說槓桿時逐字相同」的驗收情境；已列在 US-01、US-03、US-05、US-06 |
| 強平價算反邊 | 多倉的強平價寫到上方去，仍然是一個看起來完全合理的價格，讀數字讀不出來 | 多倉與空倉各一個驗收情境，數字互為鏡像 |
| 賠超過保證金 | 這一注帳面上可以算出負值，讓可用資金變成負的 | 「不穿倉」獨立成一條規則，並有跳空崩跌的驗收情境 |
| 誰先到搞錯 | 止損比強平遠時若仍先算止損，會憑空替使用者擋掉一次爆倉 | 兩個方向各一個驗收情境（US-05 前兩個） |
