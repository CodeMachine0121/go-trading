# PRD — 現貨機器人訊息把結論寫成「出場」

需求共識見 [BRIEF.md](BRIEF.md)。

## 範圍

一句文案。`StrategyBotMessageDomain` 的結論那一行，在現貨模式且這一輪的結論是
賣出時，動詞由「賣出」改為「出場」。

**沒有新的欄位、沒有新的取值、沒有資料庫變更、沒有 API 變更。** 信號仍然只有
買入／賣出／持有三種，交易模式仍然只有多空反手與現貨兩種。

## User Story

> 作為一位用現貨（純做多）策略機器人的使用者，
> 我希望結論那一句是我照得了的動作，
> 這樣我空手時收到訊息不會以為系統在叫我做空。

## 判斷依據來自哪裡

動詞不是拿信號去比對決定的，而是**問交易模式**：這一輪的結論要求帳戶最後持有
什麼？（`TradingModeDomain.TargetFor`）

| 交易模式 | 結論 | 要求持有 | 結論那一句 |
| :--- | :--- | :--- | :--- |
| 多空反手 | 買入 | 多倉 | 做多 |
| 多空反手 | 賣出 | 空倉 | 做空 |
| 現貨 | 買入 | 多倉 | 買入 |
| 現貨 | 賣出 | **空手** | **出場** |
| 任一 | 持有 | 不變 | 持有 |
| 認不得的模式 | 賣出 | **不變**（不是空手） | 賣出（照抄信號） |

最後一列是**白撿的**：認不得的模式對賣出要求的是「不變」而不是「空手」，所以它
自動落回照抄信號，不必為它多寫一個判斷。

## Acceptance Criteria

```gherkin
Scenario: 現貨機器人的賣出結論寫成出場
  Given 一台機器人照現貨模式的規則跑完一輪
  And 這一輪的結論是賣出
  When 它把那一輪寫成訊息
  Then 結論那一句寫「出場」
  And 訊息裡不出現「【賣出】」

Scenario: 現貨機器人的買入結論不變
  Given 一台機器人照現貨模式的規則跑完一輪
  And 這一輪的結論是買入
  When 它把那一輪寫成訊息
  Then 結論那一句照樣寫「買入」

Scenario: 各來源怎麼說照樣寫信號
  Given 一台機器人照現貨模式的規則跑完一輪
  And 這一輪的結論是賣出
  And 其中一個信號來源說賣出
  When 它把那一輪寫成訊息
  Then 結論那一句寫「出場」
  And 那個來源那一行照樣寫「賣出」

Scenario Outline: 合約型一個字都不改
  Given 一台機器人照多空反手模式的規則跑完一輪
  And 這一輪的結論是 <結論>
  When 它把那一輪寫成訊息
  Then 結論那一句寫 <那一句>

  Examples:
    | 結論 | 那一句 |
    | 買入 | 做多   |
    | 賣出 | 做空   |

Scenario: 持有兩種模式都照抄信號
  Given 一台機器人跑完一輪
  And 這一輪的結論是持有
  When 它把那一輪寫成訊息
  Then 結論那一句寫「持有」

Scenario: 認不得的交易模式照抄信號、不發明動作
  Given 一台機器人的規則帶著一個系統讀不懂的交易模式
  And 這一輪的結論是賣出
  When 它把那一輪寫成訊息
  Then 結論那一句照樣寫「賣出」
  And 訊息裡不出現那一行交易模式
```

## 對既有文件的影響

- `UL-MAP.md` 的「現貨」那一條：原本寫「機器人訊息在這個模式下**一個字都不改**」，
  已改寫成「把結論寫成**買入／出場**」並記下理由。
- `UL-MAP.md` 的「多空反手」那一條不動。
- `2026-09-18-trading-strategy-trading-mode` 的 BRIEF／PRD **不回頭改**；那一次的
  決定由本切片接手取代，理由寫在 BRIEF。

## 不在範圍

- 「買入」改「進場」。
- 合約型的任何文案。
- 「各來源怎麼說」那幾行。
- 執行紀錄存的結果。
- 機器人名字（使用者自己取的，系統不碰）。
